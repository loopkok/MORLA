# MMK2 遥操排查与修复流水（2026-11-11 晚至 11-12）

以下按排查和修复的先后顺序记录，包含此前用于定位的对照轮次。实测手感、日志统计、合成回放和测试结果分别标明。逐帧数据、运行编号和复算脚本见[原始节奏调查](README.md)，更早的修复见[项目变更记录](../../../CHANGELOG.md)。

## 1. 确认 Quest 入口与双臂消费频率

**现象。** 同一套 Quest 输入驱动 FR3、CR5 单臂约 90 Hz。MMK2 单臂也有卡顿，双臂约 35–40 Hz，部分轮次仅右手按 Grip 时左臂在仿真中也动，左手先按偶尔无法开始。

**排查。** 用接收器的每侧序号与引擎实际收到的新位姿对照。原始双手卡顿轮次接收端每侧约 180 个序号每秒，约合 90 个位姿每秒。引擎实际消费左 39.5 Hz、右 33.5 Hz，指令左 35.6 Hz、右 29.3 Hz。另三轮对照的 trace 写盘有丢失，原始行数不能直接当作命令率。

**改动与结果。** 左 Grip 也能发起全局遥操，实际跟随仍由各侧绑定门控。松开、来源消失或输入坐标基不匹配时，重置对应绑定并清理 SDK 中待发送目标，底盘释放时排队零速度。代码和回归覆盖了这些触发路径，左右 Grip 的组合仍需用实体 Quest 复测。此前数据支持掉帧发生在接收之后的消费路径。旧轮次的日志无法单独判定串臂来自门控、残留目标还是映射配置。 [原始频率统计](results/rates.txt) · [绑定门控](../../../src/common/morla_teleop/morla_teleop/engine.py) · [SDK 目标释放](../../../src/robots/airbot/morla_mmk2_driver/morla_mmk2_driver/session.py)

## 2. 解耦输入处理与仿真步进

**现象。** 未按 Grip 时输入线程空闲，一发双臂指令就明显降频。BEST_EFFORT、depth=1 的订阅在消费跟不上时只保留最新样本。

**定位。** 仿真提交的 `command_request → command_receipt` 为 p50 6.15 ms、p95 20.58 ms，同步控制计算 p50 1.23 ms。提交区间包含校验和调度。代码核查确认仿真步进和快照曾持有命令锁，同步输出整形也做过 FK。IK 已在异步 worker 中，求解耗时主要增加候选年龄和计算负载。

**改动与结果。** 分离命令入队锁与仿真步进锁，将输出 FK 诊断移到对应臂的 worker。双臂保持各一个独立求解进程。提交可在快照受阻时继续，联合回归 175 项通过。固定关节目标、每臂 90 Hz 的本地双臂基准中，提交 p95 由 0.708 ms 降至 0.499 ms。该基准未复现原始长尾。 [逐段计时](results/frame_cost.txt) · 提交 `c689e0c`

## 3. 用相机和显示方式做对照

**现象。** 手柄到关节命令的时延无法解释 MuJoCo 窗口看到的全部卡顿。同一段位姿直接回放较流畅。通过 Web 同开浏览器与本机窗口时更卡，只开本机窗口有所改善，但 Web 仍在显示三路相机。

**对照与结果。** 操作员在系统编排里删掉四个仿真相机配置，再只开本机 MuJoCo 窗口测试，报告平移基本跟手。保留该组合作为 IK 手感对照。相机和显示负载对这组工况有明显影响，现有记录未分别量化每路相机、浏览器预览和本机窗口的开销。剩余问题集中在旋转慢、停住或抖动，以及加一点旋转就拖慢平移。

## 4. 修正目标跟随、限步和静止抖动

**现象。** 早期回放中手停后机械臂仍追不平。后续一轮即使平移也慢，输出步长中位数仅为当拍允许上限的 33%。再后来，将速度设为 1.6 rad/s、步长设为 0.3 rad 后，操作员报告静止时双臂持续抖动。

**改动。** 每次从原始手柄目标重新推导有效目标，避免把截断后的目标跨拍累积。求解器用自己的内部步长，异步结果作为绝对关节目标交给输出端。输出保留实测领先窗口和整组关节的同比例限步，取消第二次输出 FK 拒绝。贴关节限位时限制向外的分量，再用其余自由度求解。

**结果。** 早期同录制逐拍闭环复放末拍误差由 0.585 m / 1.233 rad 降至 0。输出修复后的恒定偏移桩回放，步长中位数达到各档当拍限值。后续操作员报告静止抖动已消失，但混合旋转和平移时仍慢。本轮没有隔离静止抖动的单一触发点。 [输出与目标修复记录](../../../CHANGELOG.md) · 提交 `492d1c2`、`8370560`

## 5. 对照腕部约束和数值方法

**现象。** 单独平移较跟手，加入少量旋转时平移也明显变慢。腕部接近奇异位形时，旋转补偿可能要求多个关节协同；任一关节达到当拍上限后，输出同比例缩小整组步长。

**改动。** 提供可关闭的 TCP 位置护栏。微分法可在同一有效目标内做 1–3 次迭代；新增 URDF 有界数值模式，直接拟合完整目标位姿，使用独立的单臂 worker，继续通过公共输出约束。

**结果。** 操作员报告微分法两次迭代、2.0 rad/s 时平移和旋转都比较跟手，一次迭代反而差一些，主观仍不及 Astral。保留两次迭代、2.0 rad/s 为该仿真对照基线。护栏开关与求解模式的手感差异仍需同一实体 Quest 轨迹复测。 [微分实现](../../../src/robots/airbot/morla_mmk2_teleop/morla_mmk2_teleop/urdf_ik.py) · [有界数值实现](../../../src/robots/airbot/morla_mmk2_teleop/morla_mmk2_teleop/urdf_least_squares.py)

## 6. 增加 DH 闭式解析模式并部署

**现象。** 分拣 Demo 的单臂闭式 IK 有直接枚举分支和腕部奇异处理。三组同关节角的 FK 对照中，Demo 与 MORLA TCP 位置相差 11.3–14.8 mm，不能直接使用 Demo 的 DH 参数。

**改动。** 移植解析分支枚举，使用 MORLA 对应的 DH 几何、TCP 和有效关节限位。优先选接近参考关节的解，J5 接近零时在 J4/J6 间分配旋转，最终用 URDF FK 校验。左右臂继续独立并行。Web 在「遥操配置 → 末端位姿跟随 · MMK2 → 输入时效与求解设置」增加「DH 闭式解析求解」。左右绑定分别配置，保存后重新启动工作站。

**结果。** 本地 2,800 组 URDF FK 目标通过，含随机位形、腕部奇异和关节边界。90 Hz 双臂合成回放中，解析求解 p95 约 2.0 ms/臂，两臂各取得 178 个诊断样本、无保持帧，输出符合 2.0 rad/s 上限。同轨迹有界数值 p95 6.0–7.8 ms，微分 4.4–4.7 ms。这些是求解耗时，未测 Quest 到机械臂的端到端延迟。

部署主机保留现场节拍探针，构建并重启 Web 后确认 API 和浏览器静态资源均有新模式。远端 47 项 Web 测试、双臂解析模式 MuJoCo 集成测试通过；旧有界数值模式有一项首跑未改善代价，测试进程限制 BLAS 线程后 14 项 IK 测试通过。 [解析实现](../../../src/robots/airbot/morla_mmk2_teleop/morla_mmk2_teleop/analytic_dh.py)

## 7. 真机连接、发送节奏和反馈阻塞

**改动。** SDK 发送循环将 RPC 耗时计入周期，避免在固定等待之外再叠加完整 RPC 时间。增加 MMK2 工作位配置及驱动限位约束。配置频率是目标发送节奏，真实发送率和运动速度仍取决于 RPC、控制接口、固件和反馈。

**现场结果。** 真机启动工作站出现 `MMK2_JOINT_ERROR`。在真实设备模式下，这说明主机已通过 SDK 收到 gRPC 状态流；驱动在收到非零关节错误码，或错误码列表长度与关节名不一致时拒绝该帧。现有 Web 错误无法区分两种原因，真机尚未达到可遥操状态。下一次用只读 SDK 记录原始 `joint_state.name`、`error_code` 及其长度，再决定检查具体轴还是服务端协议。MORLA 连接地址填写 SDK 实际可达的 gRPC 服务端，模板为 `172.25.14.1:50055`。 [反馈校验](../../../src/robots/airbot/morla_mmk2_driver/morla_mmk2_driver/feedback.py) · [真机配置](../../../src/robots/airbot/morla_mmk2_driver/README.md)

## 后续复测顺序

1. 真机先读原始反馈，定位 `MMK2_JOINT_ERROR`，确认反馈就绪。
2. 用同一台主机、同一段输入分别验证仅左 Grip、仅右 Grip 和双 Grip。仿真先固定为本机窗口、相机移除，逐项恢复相机和浏览器显示。
3. 固定工作位、滤波、输出速度和步长，比较三种 IK 的按侧输入消费率、求解结果率、保持帧、输出限幅比例和关节反馈。对比纯平移、纯旋转、平移加旋转、松手和静止工况。开启详细 trace 的运行单独标注，以便对照写盘丢失和运行开销。
