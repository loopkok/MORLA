# Nero / Quest 3 遥操链路排查记录（2026-10-20）

对照用户确认可用的 `/home/loopkok/xnero_ws`，检查远程 `/home/loopkok/MORLA` 的双 Nero、双 XHand 链路。Quest 已安装带时间同步的 MORLA 新应用，旧 APK 的 UDP 裸文本协议不兼容问题不适用于当前配置。

检查时远程只有 Web 运行，机器人 Profile 未运行，`adb devices` 无设备。因此下列结论来自源码、独立 ROS 域的软件探针和 IK 数学回归，不是 Quest 已连接时的实体联调验收。未启动真机驱动、使能、复位或发送硬件运动命令。

## 已核对的主链路

新版 Quest 应用 → ADB reverse / TCP 8000 → `morla_input` 时间同步与包检查 → 左右腕位姿 / 手部关键点。

- 手臂：坐标变换 → `nero_arm_teleop` 实测关节锚定、相对位姿、IK 和关节过滤 → 具名七关节命令 → `nero_robot_driver` → CAN → 控制器。
- 手：关键点预处理 → DexPilot → 具名十二关节命令 → `xhand_adapter` → 原生串口驱动 → XHand。
- Web：统一控制协调器 → 开始/暂停和控制权信号 → 两臂与两手命令写入节点。

与旧工程对照结果：位姿处理和安全过滤数学主体一致，Quest 输入新坐标基与 Profile 补偿通过等价性测试；DexPilot 左右 YAML 与实际旧工程完全相同；手关节名字、弧度单位和右手食指符号处理一致。IK 的 DH/FK 数学一致，但冗余角采样有调整，不能称整个求解器完全相同。旧工作位附近 32 个目标、当前左右工作位附近 32 个目标，两版均全部求解成功；这不覆盖全部工作范围和奇异位形。

实际运行参数存在差异：旧全双臂启动配置为 50 Hz、位置平滑 0.5，新版 125 Hz、位置平滑 0.8；新版驱动另有限速。运动比例均为 0.65。旧工程拇指修正默认关闭，新版 Nero 打开，可能改变拇指抓握手感。串口状态循环由旧 100 Hz 改为 50 Hz。

## 排查时复现的逻辑问题（修复结果见后文）

1. **“开始遥操”没有确认实体驱动已允许流式控制。** `control_coordinator_node.py` 的 `_dispatch_mode(start)` 发布开始信号，`_operation_confirmed(start)` 主要以写入者 armed 状态确认完成。实测关节和腕位姿新鲜时，手臂写入者可以 armed，而驱动的 `enabled/streaming_enabled` 仍为 false。内存探针复现此状态仍返回开始完成。工作位完成后保持 J 模式，这一缺口可能表现为 Web 显示开始、手指跟随，但手臂拒绝流式命令。应在开始与确认阶段检查所有配置驱动的控制器、电机、反馈和流式许可，并检查手部实际反馈；不能用写入者 armed 替代硬件就绪。

2. **Quest 输入超时过长，期间继续发布旧目标。** 旧工程右臂数据超时为 0.5 秒、左臂 1.5 秒，新版两侧 YAML 均为 5 秒。真实遥操节点的隔离探针确认：腕输入停止 1.6 秒仍 armed 并发布命令，5.1 秒才 disarm。驱动不断收到这些命令，其命令看门狗不能判断上游腕输入已停止。TCP 断开处理也没有立即发布失效事件。应缩短输入超时，断连即冻结，并要求恢复后重新锚定。

3. **手臂的输入会话订阅被命名空间改变。** `teleop_node.py` 使用相对名 `quest3/input_epoch`，左右节点实际订阅各自命名空间下的话题，接收不到根话题 `/quest3/input_epoch`。根命名空间的全局启动门仍会在会话改变时发送 disarm，因此不是完全没有断连保护；但通用 disarm 保留旧腕缓存，专用 epoch 回调才会清空缓存与预备锚定令牌。探针确认了订阅解析与缓存保留。应改为绝对话题并确保新会话数据到达前不能重新锚定。

4. **HUMAN 控制权心跳过期后，手臂控制循环仍可继续发布。** 手臂在策略状态回调中判断控制权，但控制循环没有逐周期检查租约过期。隔离探针将 HUMAN 租约置为过期，`manual_allowed` 为 false，节点仍 armed 且发布一帧。手部节点会检查租约，导致双臂与双手行为不一致。该问题适用于启用策略/HITL 控制权时，应在控制循环中主动冻结过期控制权。

## 本次按用户要求已修改：暂时关闭 Nero 工作空间

当前 HOME `[0,85,0,0,0,0,0]` 的求解器末端距基座约 0.6082 m，超出原 0.58 m 球形空间。旧逻辑即使手保持原位，也会将该目标向内投影约 0.0282 m；对应的一次数学 IK 解存在明显关节变化。该结果说明目标会被改变，不代表已实际观测到真机运动幅度或速度。

新增 `workspace_enabled` 参数，两侧遥操配置及 Nero 节点默认均为 false，关闭球形和 XYZ 工作空间投影。原边界值保留，恢复时在左右配置中设置 true 并重启 Profile。现有关节限位、步长限制、驱动速度限制、已配置碰撞检查、输入/反馈超时与急停逻辑不受该开关影响；HOME 和工作位轨迹不变。

该修改解决空间投影问题。本轮继续对固定目标复用 IK 解，避免冗余角在重复求解时漂移；以下记录后续修复情况。

## 本轮修复结果

- **启动准入与确认**：真机 Nero 的所有配置手臂必须报告新鲜实测关节、正常控制器、全部电机已使能、新鲜电机反馈、流式控制许可，且无位置动作。腕数据、所有配置 XHand 的实测反馈和手部关键点也必须新鲜。仿真不要求真机驱动状态；其他机器人不套用 Nero 的硬件契约。开始请求在分发前检查，开始确认阶段继续检查，并等待本次请求之后各写入者的新状态。未就绪或超时会撤销 armed 并冻结输出，不会自动使能或移动到工作位。Web 顶部显示实际未就绪原因，较多原因可展开查看。
- **输入中断**：左右 Nero `data_timeout_s` 均为 0.5 秒，按源时间戳计算有效年龄；旧帧不能因刚收到就重新获得完整时效。接收端增加 0.5 秒运动流看门狗和 50 ms 检查周期，支持 Quest 多条独立 TCP 连接。某个已活跃的腕、关键点、头部或身体流超时、连接断开或同一流换连接时发布冻结和 epoch。事件驱动按钮不当作运动心跳。已被替换的旧连接关闭不会误停新连接。解析与失效处理串行，防止并发线程清空新帧。
- **重连与重锚定**：双臂、双手均订阅绝对且持久化的 `/quest3/input_epoch`。冻结会清理手臂腕缓存、锚定令牌、目标解缓存，epoch 也清理手部输入和滤波目标。时间戳早于失效边界的排队帧不能恢复输入。数据恢复后不会自动重新 armed，需点击 Web 开始或释放后重新按下开始按键。已提交 HUMAN 控制权下的显式开始允许从新鲜实测关节重新锚定；尚未提交的预备接管令牌不能被绕过。
- **控制权过期**：手臂每个控制周期检查租约，主动冻结过期 HUMAN 或禁止手动输出的状态；手部定时检查租约和关键点时效。重复 HUMAN 心跳不重新打开已冻结的手，重复 IDLE 心跳也不会撤销已经明确开始的手部输出。
- **XHand 真实反馈**：原生串口驱动检查 SDK 读取结果和关节有限值，失败时不发布带新时间戳的缓存状态。适配器检查源时间戳并发布 `feedback_fresh`；没有新鲜实测反馈时拒绝继续转发手指命令。该检查作用于共享 XHand 适配器，包括使用它的其他机器人。
- **零输入保持**：锚定后将实测关节作为首个已知 IK 解；完全相同的笛卡尔目标复用已有解，关节过滤器仍逐周期执行。当前工作位及最终 HOME 的零输入测试均保持原实测关节，不重新求解冗余角。新目标仍经过原 IK、关节限位和步长过滤，驱动限速不变。

运动比例、平滑参数、IK 搜索采样、拇指修正、串口状态发布频率未按旧工程盲目回退。视频 8765 是独立可选链路，未在本次纯遥操修复中新增视频启动逻辑。
