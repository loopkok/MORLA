## 本轮代码变更

### Nero 驱动独立流式速度

- `nero_robot_control/driver_node.py` 新增 `stream_j_speed_percent`。启动默认 0 表示继承 `position_speed_percent`；钢琴专用外部 launch 明确传 5%。启动检查允许整数 0～100，运行时修改只接受整数 1～100，原生途经点动作进行中拒绝修改。
- 参数回调只验证；控制周期更新 SDK 适配器的请求值，实际 SDK I/O 沿用已有串行工作线程。新增 `rcl_interfaces` 包依赖。
- 状态区分请求 `stream_j_speed_percent` 与 SDK 成功应用的 `stream_applied_speed_percent`，同时保留工作位和 HOME 速度字段。
- `sdk_adapter.py` 在 J 模式流式发送前发现百分比变化时调用 `set_speed_percent()`，成功后记录应用值，再执行原有相同目标去重。切换速度不需要新目标、不重复发送保持位置，也不重新使能或复位。
- Fake SDK 补齐速度状态；新增内存协议用例验证 5→10→15→5%、重复相同保持目标只产生一次位置调用。

驱动提供通用 1～100 范围，钢琴配置层另外限制为 1～20；不能把驱动范围当作已验收的钢琴速度范围。SDK 成功应用值是软件调用结果，不是电机实测速率。

### Web、worker 与双项目协议

- `piano_worker.py` 引用外部新接口 `performance_timing()`，上报左右臂请求/应用速度。新 worker 必须搭配本轮 MORLA-piano 引擎，不能单文件部署到旧引擎。
- 单键移位试动使用演奏专用规划值，先等待调速确认，再开始位移计时；健康退出时恢复基础 SDK 速度。
- `PianoTab.tsx` 增加可选的演奏速度参数区和 SDK 应用回执显示。启用初值为 10%、0.225 rad/s、换位至少 0.45 s、稳定 0.2 s、抬指至少 0.12 s、按住至少 0.15 s。
- 基础 timing 保留为准备、回位、点动等动作使用。页面提示保存、重建会话和重新预检，并明确百分比不等于实测速度。
- `pianoTypes.ts` 增加可选 performance 与 arm_speed 字段。生产前端已在本次重新构建，JS hash 资源与 index.html 一起提交，旧 JS 删除；不是只提交源码而继续交付旧页面。

独立引擎在曲谱时钟启动前确认双侧切换，保持目标与反馈检查持续执行；结束和健康停止时恢复基础速度。日志采样与配置校验细节见 [外部引擎本轮日志](../../../MORLA-piano/docs/DEBUG_LOG_2026-10-23.md)。
