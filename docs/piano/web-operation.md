# 钢琴 Web 操作

MORLA Web 新增「钢琴工作台」，原有机器人操作、监控与采集、健康、数据处理页面保留。演奏核心仍位于独立项目 `MORLA-piano`，Web 增加独立进程管理、界面和互斥保护。原 Profile、遥操参数和采集数据格式不存储钢琴标定。

## 启动

正常启动 Web 后进入「钢琴工作台」。外部项目默认从 MORLA 同级 `MORLA-piano` 查找，远端为 `/home/loopkok/MORLA-piano`。

仍可在MORLA目录运行 `bash scripts/nero_web_start.sh`。本次修复已部署并重启，页面须强制刷新（Ctrl+Shift+R）以加载新按钮和恢复逻辑。当前设备标定完整性尚未确认，位置试动前先核对 [SDK诊断误写记录](sdk-probe-incident.md)，不能把软件测试通过当作手部标定已经正常。

可选环境变量：

```bash
export MORLA_PIANO_PROJECT=/home/loopkok/MORLA-piano
export MORLA_PIANO_DATA=/home/loopkok/MORLA/.morla_piano
export MORLA_PIANO_PYTHON=/usr/bin/python3
source /opt/ros/humble/setup.bash
source /home/loopkok/MORLA/install/setup.bash
ros2 launch morla_web_manager web_manager.launch.py web_host:=0.0.0.0 web_port:=8080
```

Python 默认与 Web 相同，ROS 模式须能导入 rclpy。重新安装 Web 包使用 `colcon build --packages-select morla_web_manager --symlink-install`；前端交付于 `web/dist`，无需开发服务器。

## 三种运行模式

- **纯软件演练**：不依赖 ROS，不打开 CAN/串口，可验证页面、参数和完整曲谱流程。
- **ROS fake**：启动 MORLA Nero fake 驱动、XHand 适配器和双手软件后端，验证真实 ROS 链路。
- **真机**：启动外部项目的独立驱动 launch，需填写左右不同的 CAN 及串口。不会启动遥操、Quest 重定向、策略或采集。

建立会话前，先在原页面停止原 Profile、采集与推理；命令行启动的相关节点也须停止。Web 不会自动终止其他机器人进程。Quest/语音输入预览可以保留，但钢琴不消费这些输入。

## 在线操作与重新标定

初始工作位和琴键演奏零位分开保存。打开「参数与标定」，勾选「允许当前目标用于标定试动」后，即可从当前实测位置直接点动，不会自动移动到旧演奏零位。

### 工作位

先在「点动 / 工作位 / 标定侧」选择左臂或右臂，再点击对应的「左臂/右臂沿 MORLA 四段轨迹 → 钢琴工作位」。操作仅对选中臂调用 position / position_point2 / position_point3 / position_point4，使用该臂原四段SDK J轨迹；只判定本侧实测到位并稳定0.2秒才进入下一段，另一臂的位置误差不参与。前四段最大单关节误差容许3°，驱动与Web一致；完成后仅对本侧恢复流式使能、限速插值到本侧钢琴工作位（第5段），第五段仍使用配置中的演奏到位容差。原Profile默认途经点容差约1.15°，HOME容差与原轨迹配置保持不变。

工作位期间控制范围锁定为所选臂：不会给另一臂或手指发布位置目标，也不会使能另一臂。操作中选择框禁用，进度标注实际执行侧。完成后可选择另一侧，独立执行其工作位流程。全局停止、急停和故障保护仍可停止双臂。之后执行演奏「准备」会重新申请双臂双手控制权，单侧工作位不等于整套演奏已经准备好。

工作位API要求显式 `side=left/right/both`；页面只提交当前选择的left/right。旧页面未传side时拒绝，不会静默执行双臂；应强制刷新页面。

钢琴工作位按各侧原生 J1—J7、单位度保存：

```text
左：-25.915 90.973 -37.488 72.655 155.000 -40.201 5.965
右： 28.249 98.000  38.828 58.867 -155.000 46.206 -3.757
```

用户原始数值的左 J5=159.967°、右 J2=104.079°、右 J5=−160.440°超过当前限位；经用户授权，以上分别暂用155°、98°、−155°。硬限位未放宽。这组工作位只经过软件和 fake 验证，实际路径净空仍须现场确认。

J 轨迹执行中按停止会请求两臂电子急停，不能用 JS 保持指令取消 J 规划；此时进入故障状态，核验设备后断开、重新连接。不会自动接续第5段或演奏。

### 点动、读数和关节调节

- 标定侧选择左臂/左手或右臂/右手。实测角度、反馈年龄及 link7 的 XYZ/RPY 随会话更新；输入框为目标，点击「发送」才运动。
- 机械臂关节目标使用度，J1—J7按原生顺序；每次与实测位置相差不超过15°，以配置的臂关节速度限速插值。输入较远目标须分步调节。
- 灵巧手全部12个关节可独立调节，含拇指；每次差值最多30°，速度上限0.25rad/s。拇指仅用于手动摆放，仍不参与曲谱演奏。
- 「实测 → 输入目标」将读数复制到输入框，不发送运动。
- 笛卡尔点动是每点击一次执行一个有限段。平移步长最多5mm、旋转最多3°，默认1mm / 0.5°。选择本侧机械臂基座轴或本侧 link7 工具自身轴，支持 X/Y/Z 和 RX/RY/RZ。
- 运动学使用 MORLA 原 Nero FK 契约：本侧 base_link → link7；并非指尖或琴键坐标。旋转保持 link7 原点位置，平移保持末端朝向。先计算整段的连续限位内逆解，通过FK残差及关节连续性检查后才输出；失败不会猜一个目标。
- 两臂基座轴是各自坐标系，镜像安装下不要把左/右轴直接当成同一个琴面方向。
- 手动调节完成后状态为「手动标定就绪」，不会沿用旧 READY 开始曲谱。
- 手动标定时「停止」保持当前实测关节，避免自动跳到旧悬停值；需要抬指时点击「本侧手移到草稿悬停姿态」。演奏停止仍按原流程抬指。

### 推荐重新标定顺序

1. 将琴面固定，停止原机器人/采集/推理通道，再建立钢琴真机会话。确认左右 CAN 与串口对应正确，手侧以其安装的Web机械臂侧为准，并用无力状态下的实体手指/反馈关联验证，不凭串口尾号固定推断。2026-10-22当前现场实测修正为FTAEFQWY对应左臂末端手、FTAAUYUK对应另一侧；更换接线后须重验。缺少手部读数时仍可使用双臂维护入口；若控制器急停，先复位再重新检查。确认设备标定可用且手指可以松弛后，才点击「启动双手反馈（无力模式）」；等四路读数新鲜、SDK无错误后再进行下列运动。
2. 如需从收回位置展开，先执行工作位按钮。已经在琴面附近时，先检查路径净空，再决定是否需要走完整工作位路径。
3. 用笛卡尔点动及单关节调节，把左手小指对准C3、右手食指对准C4，其余手指依次向高音排列。61键默认C2—C7；不用拇指。
4. 点击「记录本侧机械臂为演奏零位」。重设零位会清除该侧旧换位实测点、黑键映射和每白键增量，并把移位范围收为[0,0]。合并读取两臂初始位也采取相同失效处理；不要把移动前的标定带到新摆放位置。
5. 用手关节调节得到不碰键的悬停姿态，点击「记录本侧手为悬停姿态」。逐指小幅调整到可靠按键位置，点击「记录该指当前角度为按下目标」，随后用「本侧手移到草稿悬停姿态」抬起。对两手八指重复。记录按下目标仅复制选定手指的具名关节。
6. 从零位点动到+1白键位置，选择对应步数，点击「记录换位实测点」。需要近似统一增量时，点击「计算每白键增量」，以(当前−零位)/步数计算。步数是相对零位的绝对索引，不是累计移动次数。
7. 对乐曲实际用到的其他位置逐一标定。记录实测点会扩展草稿索引范围；范围内未记录的点会使用增量生成，因此须检查每个实际使用位置和移动路径，不能只记录远端一点就认证整段区域。黑键仍须显式key_overrides及专用姿态。
8. 可以在同一会话连续点动和记录多个位置。记录只进入草稿，不改变本次会话的既有演奏配置。全部完成后断开、检查并保存，再重新连接。参数配置栏为rad，在线关节控制和工作位栏为度，不可混填。
9. 用保存参数准备、逐指试按、逐步测试换位；有修改就再次保存和重连。确认初始位、手指角度及所有使用路径后，勾选整套配置认证并保存、重连，才允许真机整曲演奏。

实测到位只确认关节角，不代表检测到琴键接触或正确声音。机械臂使用限速插值和短段IK，没有环境碰撞规划；须现场检查琴面、桌面、双臂、手指之间的净空。

## 演奏和换曲

保存参数 → 建立会话 → 选择/导入曲谱 → 调整 BPM → 预检时序/指法 → 移动到初始位 → 等待「已到初始位」→ 开始演奏。每次重播须重新准备，双手移位均为0才允许从曲首开始。

时序表中 `start` 为从曲首起算的绝对拍，`duration` 为时值，`gate` 为按住占比，`hand` 为 left/right。音符支持 C3、1-、1、1+、key:13、midi:60、0休止，指法可显式指定。CSV 导入使用界面 BPM 和保存的调号。图片谱需先整理为时序表，未实现 OCR。

单文件上限512KB、5000项事件，最多200首，单次计划最长2小时。曲谱名称不参与文件路径，后台使用随机 ID。换位来不及、重叠音、未标定黑键、出界键位、过短按键时值会在预检阶段拒绝。

## 停止、失联与控制权

- 「停止 / 抬指」可取消准备、试按、换位或演奏；反馈健康时保持实测臂位并抬指。
- 钢琴页和全局工具栏均可请求急停，急停不受普通任务互斥锁阻塞。
- 浏览器每秒续租；稳定空闲状态（含等待反馈、已准备、标定空闲、停止、结束、故障）保留180秒，适应后台标签页定时器节流。运行命令、准备、点动、演奏及尚未稳定的状态仍为6秒失联停止并释放；SDK反馈时效与执行进程看门狗不受空闲宽限影响。空闲180秒也不代表可以直接恢复运动：任何新操作前先确认新的浏览器心跳，不会自动接续旧动作。
- 切换MORLA内部功能页会保留已打开的钢琴组件和会话，其他页面显示会话仍占用的提示，原控制互斥继续有效。切回浏览器标签页或重新聚焦窗口时立即续租并重查状态。短暂心跳网络错误不会永久丢失本页面控制权；请求4秒超时后可重试，旧token的迟到结果不能恢复控制权。关闭或导航离开整个网页仍尝试主动释放，真正断网/冻结超过对应时限则清理会话。实际演奏时应保持页面正常运行，浏览器冻结超过6秒仍会停止。
- Web 与执行进程另有2秒 IPC 心跳。执行进程突退时启动仅急停、不使能/不移动的恢复进程，再清理本次驱动组。
- 执行进程须持续回传状态；首帧等待最多15秒，此后2.5秒没有状态即按失联处理并请求仅停止恢复。前端反馈年龄随真实等待时间增长，不会冻结成旧的几毫秒读数。
- 同一 ROS 域的钢琴会话互斥；真机会话另有跨 ROS 域的主机资源锁，子进程继承锁。
- 钢琴占用期间，原机器人、遥操、采集、推理和 Profile 修改接口返回409；监控、视频及离线数据处理继续可用。断开清理完成后恢复原控制入口。
- 执行中检测外部命令发布者、原生双手接口重复发布、协调器/采集节点进入、反馈过期、跟踪误差和控制器异常，发现后停止输出。

「复位急停」常驻页面顶部，与「急停」并列；纯软件/ROS fake模式不可用。真机会话建立后可操作。尚未取得运动控制权时直接请求复位；已处于故障或取得控制权的空闲会话，点击并确认后，页面会自动结束旧会话、等待ROS资源退场、重建维护会话，再仅请求复位。过程中保留未保存标定草稿，不续跑旧工作位或曲谱；停止/急停或离开页面可取消恢复。完成后点击「重新检查反馈」，确认正常后再单独准备。控制器报告急停时禁用运动按钮，执行进程也会在取得运动权之前拒绝运动请求。复位不会自动使能、移动或恢复演奏。

CAN 初始化包含电机使能，须单独确认；完成结果要求新的 CAN 初始化序号、双臂 ready、实测反馈及电机状态正常。复位结果要求新的复位序号、双臂 cleared 和新鲜的控制器正常/抱闸未释放状态；服务返回“已接纳”不会提前报告成功。操作中停止会取消等待并请求电子停止。完成后点击「重新检查反馈」，不自动准备或演奏。

建立会话后立即进入持续反馈检查，缺失读数不会占用命令处理；「重新检查反馈」只检查当前数据，不再等待连接超时。双臂维护仅依赖双臂状态接口，不要求双手或关节读数先到齐。某一路收到新有效样本后可以清除该路输入错误，其他路的错误不会被覆盖。运动中发生错误仍会进入故障状态，不能用后续读数自动恢复旧动作。

断开会话时按本次会话的随机进程标记清理 ROS launch 及其子进程，先给正常退出机会，再逐级终止；Linux 下即使子进程换了进程组或被收养，也要核对 PID 启动时间后清理。未退出时显示「驱动尚未退出 · 设备仍锁定」，不能建立新会话。不会按节点名批量终止其他进程。DDS 发现图退场可能稍晚于进程退出，页面会等待占用提示清除。

钢琴专用 launch 中任一驱动退出会触发全组退出；双臂驱动仅在钢琴通道启用退出停止功能，按“已提交 SDK 调用 → 电子停止 → CAN 断开”的顺序关闭。原 Profile 默认参数不变。灵巧手保留 NEXUS 的 `read_state(id, false)`；禁止使用会重发内部命令缓存的 `force_update=true`。命令包包含保留字段全部清零，反馈使用 best effort、深度1，适配器保持单线程。

钢琴模式下，建立会话只打开串口并查询元信息，不发送手指控制包，也不把未初始化缓存当作实测。需要手部读数时，点击「启动双手反馈（无力模式）」并确认手指可以松弛：发送完整初始化的12关节无力包（mode=0，位置/增益/力矩及保留字为0），等待设备应答后才公布读数。此步骤会解除手指主动保持，不能当作纯读操作；不会发送手指位置目标或使能机械臂。取得有效演奏租约后才允许手指位置控制；停止、失联和断开转回无力状态。SDK 状态或数据无效时不刷新实测时间，页面显示对应侧 SDK 原因。

手部读数采用NEXUS的独立测量容差0.05rad（约2.86°），机械臂读数仍为0.1°；运动目标限位完全不变。无力时部分手指可能读到略小于0的角度，这些值在测量容差内会原样显示，并列出越过目标范围的具名关节；不会把它们改成0。超过测量容差仍拒绝，并显示具体关节、角度与范围。启动双手反馈只核对双手，机械臂没有CAN读数不会令手部初始化结果失败。

实测读数可显示不等于能直接作为控制目标。未记录参考时，边界外的起点仍会在申请控制权和使能前拒绝。操作员确认当前手姿正确后，可点击「记录本侧手为悬停姿态」并确认：草稿保存原始 `start_reference_rad`，悬停目标 `hover_rad` 使用最近合法边界内的角度。记录和保存都不运动、不改设备零位、不写Flash；断开保存并重连后生效。

以后明确发起位置试动时，只有与这份参考匹配、距离目标边界不超过0.05rad（2.86°）的小偏差，才允许用最近边界作为初始保持目标。首次接管可能因此小幅修正手姿；不在边界附近的关节保持原值。该规则不放宽任何发送目标限位，不更改实测值；缺少参考、偏差过大、跨到未经记录的另一边界、机械臂起点越界仍拒绝。准备、手动点动、停止保持均使用同一命令起点规则，诊断/记录始终读取原始值。设备出厂标定完整性没有因此得到证明。

双臂仍缺读数时，按页面单独处理CAN初始化（包含使能，须确认）；不要反复启动双手反馈来处理双臂问题。

真机建立前会检查串口真实设备是否重复、是否可读写，以及 CAN 是否为已启动的 CAN 接口。检查不会替代左右物理接线的确认。

软件请求不等于实体已经停稳。反馈中断时不能保证抬指成功，须检查设备和硬件急停。管理员直接运行供应商 SDK 或绕开 Web 调用 ROS 服务不受 HTTP 锁约束，钢琴运行时不得另开控制器。

## 数据和验证

数据存于 `.morla_piano/config.json`、`scores/`、`sessions/`，与原采集数据分离并加入 Git 忽略。配置使用版本比较、跨进程文件锁和原子写入；会话保存参数快照、事件日志与完整 `drivers.log`，不保存 SSH 密码。工作位故障在发送停止之前记录当时的目标角、实测角、逐关节误差和驱动状态，避免只能查看停机后的姿态。
