## 工作位

经用户确认，对原始超限角采用限位内临时值：左J5=155°，右J2=98°、J5=−155°，其余角度保持原值。完整角度见 [操作说明](web-operation.md)。不修改 SDK、IK 或驱动硬限位，也不修改原 Profile 工作位点。

工作位按钮执行原驱动四段 position 服务序列，使用 SDK J 模式；两臂每段均须状态序号、阶段、目标和实测位置一致且稳定后才能继续。四段完成后显式恢复 JS，再限速到钢琴工作位，第5段与琴键演奏零位分开。

## 对抗性检查与修正

- 输入：左右侧、部件、关节索引、有限数值、度/rad换算及硬限位在 HTTP 与执行进程两次验证。机械臂单次最多15°，手关节30°；笛卡尔每次最多5mm/3°。
- 坐标：复用 Nero 原生 FK，明示各侧 base_link → link7；分别验证左右、基座/工具轴、三个平移轴及三个旋转轴。短段全量预求解、FK残差检查、关节连续性检查通过后才发送；不可达不会猜测目标。
- 输出隔离：手动操作从实测位置建立保持目标，仅修改选定关节或机械臂；不会先执行旧 prepare，也不会把另一只手/机械臂补成零值。拇指可手动摆放，演奏仍不使用拇指。
- 停止：手动标定停止保持实测姿态，避免进入可能失效的旧悬停位；单独提供移到草稿悬停姿态的按钮。演奏停止仍抬指。原生J阶段的停止/断开立即触发急停路径，不能以JS保持伪装成已经取消J规划。
- 反馈与控制权：手动运动沿用反馈年龄、控制器、实测电机使能、所有权、冲突发布者、父子心跳和浏览器租约检查。J阶段只允许JS输出许可撤销，其余健康门槛不放宽；阶段目标/序号被改写则停止。
- 数据：重新记录演奏零位会清除该侧旧换位实测点、黑键映射与增量，并收缩范围到[0,0]。同一会话可连续调节并捕获零位、悬停、按下和换位点；保存仍需断开，并保留原版本检查和原子写入。手动调节撤销READY，禁止直接沿用旧准备状态演奏。
- 兼容：原配置自动补齐独立calibration.work_pose_deg；高级JSON缺少该字段或仅有空对象均归一化后再交给前端，避免缺字段崩溃。原运动/采集/推理接口互斥保持，未增加原通道运动入口。
- 强杀：进程强杀后DDS发现图可能暂时仍显示旧发布者，界面维持占用拦截直到退场，不忽略发布者来强行重连。测试将正常J中断验证与强杀清理分别执行。

## 急停复位入口修正

此前「复位控制器」仅在WAITING_FEEDBACK显示，已连接/故障状态下被隐藏。现改为顶部常驻「复位急停」，并显示禁用原因；执行条件由Worker实报maintenance_allowed，HTTP与执行进程同样校验。急停/故障或已取得运动权后先断开重建会话，禁止在旧运动状态上复位并续跑。维护请求需真机模式和明确确认，不会隐式使能或发送关节目标。

## 故障后复位恢复闭环

针对“工作位使能遇到arm_status=1，随后复位按钮灰色”的现场反馈，保留服务端禁止在旧FAULT/运动会话直接复位的门槛，前端提供受控恢复：原持有者确认后关闭旧会话，等待ROS占用退场，重建会话，仅发送reset。保留未保存草稿，废弃旧预检/准备状态；不调用enable、prepare、work_pose或play。

恢复期间保持新会话心跳，防止旧心跳的迟到错误撤销新控制权；停止/急停、页面退出、其他页面抢先取得资源或控制器拒绝均终止流程，不继续运动。Worker增加reset_required状态，界面在急停锁存时禁用运动入口；执行进程在claim/enable之前检查已知急停，拒绝请求但不把正常维护会话变为FAULT。已有FAULT仍可从复位按钮进入自动重建流程。

前端恢复状态机12项测试通过，覆盖直接复位、故障/已持权会话重建、DDS阻塞、会话替换、忙碌状态、取消/退出与复位拒绝；TypeScript和生产构建通过。测试使用模拟接口，未操作实体控制器。

恢复闭环候选版本Web回归177项通过、2项原有用例跳过；部署前确认钢琴会话已断开。备份为 `/home/loopkok/MORLA/log/piano-recovery-deploy-20261021-1792564404/before.tar.gz`。工作位第1段的实体到位超时仍是独立待定位问题，本次没有放宽容差或自动重试工作位。
