# 2026-10-21 SDK 诊断误写记录

本轮处理建立会话无反馈时，诊断探针错误地将 SDK 私有 `write_to_device` 当成状态请求。实际发送的是命令0x05，日志报告 `save to flash ok`；循环对两手各请求60次。候选桥接代码没有部署，发现后即停用，危险探针可执行文件已撤销执行权限并归档。

此前强制读取对比也调用过 `read_state(..., true)`；该 SDK 路径会重发内部手部命令缓存，因此不能将这些对比称为纯只读验证，也不能据此保证没有控制帧。没有故障前的设备参数快照，用户确认没有原厂标定备份，不能声称硬件标定完全未受影响，不能自动恢复或覆盖设备参数。

后续参数读取在串口写入口加白名单，仅允许文档中的读命令；实际记录只有0x15读取寄存器。SDK 返回 `is_calibrated=0`，部分标定字段异常；这些字段可能涉及已有故障、固件/SDK兼容性，或误写影响，当前无法区分，不能用作可信恢复数据。实物串口按用户确认保持：FTAAUYUK左手、FTAEFQWY右手，不按SDK手型标签互换。

硬件侧原始记录归档在部署主机 `MORLA/log/piano-sdk-probe-incident-*`。应先核对设备标定与供应商协议，再执行位置试动。本项目不会自动写设备标定、Flash、模式ID或执行厂商校准。

软件修复参考 NEXUS 的 `docs/changelog/2026-10-08-xhand-feedback.md`、原生驱动与 `command_packet.hpp`：保留被动读取、修正QoS、初始化全部命令字段。钢琴需要主动取得手部读数时，必须由操作员明确确认无力模式初始化；建立会话不自动发送手部控制包。真实 SDK 的离线报文编码测试在传输前截获，确认无力包为0x02、288字节，全部保留字清零，不使用0x05。

最终部署后只读会话验证：双臂维护接口可用，双手等待明确初始化，手部初始化代次为0，没有执行复位、使能或位置目标；反馈重检0.012秒返回，关闭后设备占用释放。此结果验证连接和维护逻辑，不能补足设备标定事前快照，也不能证明本次误写没有影响。

后续关联修正（2026-10-22）：上文YUK左/QWY右是当时人工确认记录。新现场只读关联试验显示，安装在Web左臂末端的食指弯动出现在QWY通道，操作员也确认该机械臂归属，故当前操作映射应按QWY左/YUK右重新验证；历史人工确认不作为永久接线依据。此修正不撤销上述SDK误写事件记录，也不更改设备标定或手型。
