# CR5 真机：从使能检查到 Quest3 遥操的 Web 操作手册

日期：2026-11-03。适用 MORLA 公共工作站、Linux ROS 2 Humble 主机；不加载仿真预设、不手写装配/部署文件。先独立验收 CR5，再添加真实 Quest 右手柄。

本文是按当前代码核对的操作流程，不是该机器人、固件、负载和 TCP 已完成实机验收的声明。设备参数必须使用现场实际值；没有列出的通用配置字段保持未配置，不能用全零代替未知参数。

## 操作含义和前提

- **准备设备**：检查新鲜反馈，不等于使能。
- **开始遥操**：在公共接管流程中使能机器人。配置无输入、无映射时，不主动生成遥操运动目标；实际使能仍须现场观察。
- **暂停遥操**：撤销当前输出许可、保持目标，电机通常仍使能；反馈异常时可能走失能回退。
- **停止工作站**：CR5 调用 DisableRobot()，确认后关闭连接。不是只停止网页刷新。
- **Web 急停**：软件锁存和驱动停止，不替代实体急停回路。
- **直接回工作位**：主动使能并按关节空间直线插补运动；不经过避障规划，点击前必须核对目标和路径。

需要从现场确认：控制器 IP、机器人序列号/资产身份、固件 TCP/IP 协议与 30004 反馈格式、六关节实际软件限位、关节方向和零点、负载/重心、工具 TCP。先在厂商软件检查报警、控制模式、负载、速度限制和实体急停。机器人安装固定、运动区域清空，操作者可立即操作实体急停。

驱动固定使用 29999 Dashboard、30003 ServoJ、30004 二进制反馈，见 [Dobot 官方端口说明](https://www.dobot.cn/service/faq/459.html?lang=cn)。端口连通不代表固件/反馈格式兼容。不要让两套程序同时控制同一机器人。

当前 CR5 主机命令超时自动失能保护未完整实现；不要依赖断网或松手停机。ServoJ 的 t/lookahead/gain 是当前实现参数，不能当作已针对现场固件、负载辨识后的参数。新鲜反馈、数值有效和软件测试通过也不能证明路径无碰撞。

## 构建与启动

先停止旧工作站和旧 Web/输入进程，确保当前修改已同步到控制主机。只在同一 ROS Python 环境安装和运行依赖。

```bash
cd /实际路径/MORLA
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to \
  morla_input morla_teleop morla_cr5_driver morla_web_manager
source install/setup.bash
python3 -c 'import rclpy, pinocchio, numpy, scipy, fastapi, uvicorn; print("依赖正常")'
```

以实际 IP 替换下列文字后检查网络；这些命令不发送使能或运动指令：

```bash
CR5_IP='替换为实际控制器IP'
ping -c 3 "$CR5_IP"
nc -vz "$CR5_IP" 29999
nc -vz "$CR5_IP" 30003
nc -vz "$CR5_IP" 30004
```

```bash
bash tools/start_morla_web.sh
```

浏览器打开 http://127.0.0.1:8080，进入“工作站”。不选择仿真预设，不点击“载入预设”，不导入配置。旧服务不会自动加载新代码，必须退出旧服务后重启。

## 阶段一：只接 CR5，检查反馈、使能和失能

### 顶部与设备选型

- 配置名称：`cr5_real_bench`。
- 已保存的工作站：首次不选择。
- 输入设备：不添加 Quest 或其他输入。
- 机器人与末端执行器：选择 Dobot CR5，添加一次，实例应为 `arm`。
- 显示名称：`CR5 真机`。
- 运行方式：真实设备。
- 控制频率：50 Hz。
- 相机与传感器：不添加。

其余连接参数统一在下一页填写，避免设备参数和硬件参数出现相互覆盖的值。仿真初始关节位置保持未配置，真机从实测反馈启动，不填仿真准备姿态。

### 安装与标定

保留一条 arm.base → world。单机测试时将 world 定义为机器人基座坐标系，XYZ/RPY 均为 0；这不等于外部工位已经完成标定。标定记录名称留空。

“硬件连接 → arm”填写：

- 设备标识：实际序列号或唯一资产标识，如自己的 `cr5_bench_01`。
- 设备资源标识：`cr5:实际设备标识`；不同会话使用同一设备时应一致，不能用不同名字规避资源占用。
- 控制器 IP：实际控制器 IP。
- 控制频率：50。
- 通信超时：0.2 s。
- 指令超时：保持 0.3，但该字段不代表当前已具备独立运动 watchdog。
- 关节步长 max_step_rad：保持默认 0.05，不据此推断所有下发通道都已限步长。
- joint_lower / joint_upper：各六项，按 joint1..joint6 填现场实际软件限位，单位 rad。不要照填 descriptor 的外层 ±2π，不要填六个零。
- urdf_joint_signs：现场已核对的六项方向；仅确认一致时填六个 1。
- urdf_joint_offsets：现场已核对的六项 rad 偏置；仅确认一致时填六个 0。
- initial_positions：不配置。
- 身份/运动学/停止测试复选框：只勾选实际已完成的检查，不为通过页面检查虚假勾选。
- session_id、address、serial、bus、secret_ref：无明确部署需求时留空。

角度转弧度：rad = degree × π / 180。部署限位是必填参数，不能用未确认值继续真机试验。当前工作位预检主要依据解析后的关节元数据，操作员仍须确认目标在现场实际软限位内，不能把填写限位当作所有通道已获得统一安全认证。

协同控制组不添加。“遥操作设置”不添加映射，不设置工作位。

### 数据记录与启动

保留 arm.position 观测、arm.position_target 动作；频率 30 Hz、动作来源“控制指令”，无图像/辅助输入。不开始录制。

检查与运行：开启诊断日志，反馈采样 50 Hz、容量 1024 MB。该配置没有仿真设备，不需要仿真模式或显示设置。

依次点击“检查配置 → 检查运行依赖 → 保存配置 → 启动工作站”。此阶段不点“连接输入”，因为没有输入设备。启动建立连接和读取反馈，不主动使能/回零。

展开“驱动与控制器诊断”，确认 components.arm 中：ready 为 true、values 为六个实测 rad、device_status.error_status 为 0、初始未使能时 enable_status 为 0。与厂商软件六个实际关节换算后逐项核对。反馈不符或有报警，停止在这里排查。

### 使能／暂停／失能

1. 点击“准备设备”，确认操作成功。
2. 点击“开始遥操”并确认真机提示，等待操作成功，不把“已提交”当完成。
3. 确认 enable_status=1、无异常移动。当前无输入/映射，不应生成遥操目标。
4. 点击“暂停遥操”：保持当前位置，电机通常仍使能。页面 READY_DISARMED 是框架输出许可状态，不等于控制器已失能。
5. 点击“停止工作站”：确认厂商软件上机器人实际失能。停止后连接关闭，Web 不一定还能读到最终反馈，不能仅凭 STOPPED 判断电机状态。
6. 重新启动同配置重复一次，确认使能、暂停和失能行为一致。

异常运动、使能/失能不确认、错误或反馈不一致时，不进入下一阶段。

## 阶段二：不接 Quest，验证小幅关节运动

当前公共 Web 没有完整关节点动面板，使用“直接回工作位”检查关节插补链路。它会主动使能并运动，不是只修改一个配置值。

先记录阶段一反馈的实际 q1..q6（rad）。停止工作站，将配置名称改为 `cr5_real_joint_test`。仍只有 arm。

“遥操作设置 → 直接回工作位”：勾选设置 arm 工作位，六个目标先填刚读取的当前实测值，速度填 0.01 rad/s。检查、保存并启动后，再次读取反馈；确认姿态仍与目标一致。不一致则停止、更新目标并重新核对，不能使用失能前的旧反馈盲目运动。

确认后点击“直接回工作位”。第一次同位姿目标应完成而没有明显位移。再停止工作站编辑目标，只对现场确认有足够空间的一轴增加 0.01 rad（约 0.57°），其他五轴保持当前值。重新保存、启动并核对反馈后才执行。选择哪一轴必须按现场工具、线缆、限位和路径决定，不默认 J6 或任何轴绝对安全。

检查实际运动轴、方向、幅度、速度、到位反馈以及暂停中断行为。最终“停止工作站”并确认实际失能。禁止把工作位填成全零，禁止把仿真初始姿态直接用作真机第一条目标。

## 阶段三：添加 Quest 右手柄

前两阶段通过后停止工作站，将配置另存为 `cr5_quest_real`，保留 arm 的真实参数。取消勾选工作位，避免左 X 意外触发移动。不添加仿真相机；真实机器人不会自动出现在 MuJoCo 画面中。

### Quest 设备

添加 Quest 3，实例 quest：显示名称“Quest3 右手柄”、真实设备、右侧、由 MORLA 启动、TCP 有线、TCP 端口 8000。UDP 端口、输入话题、命名空间及其他 CAN/串口参数留空。硬件连接填写设备标识 `quest3_right_usb`，资源标识可用 `quest:tracking:8000`；其他参数沿用前页，不在 Quest 中填机器人 IP。

### 控制映射

添加一次映射，先选择 quest.right_pose → arm.position_target，控制方式“末端位姿跟随 · CR5”，再填写跟随参数，避免切换控制器时参数重置。

- 输入有效期：250 ms。
- IK：连续微分跟随。
- 首次真机的运动使能：quest.right_hold，先验证按住模式。
- 位移倍率：0.1。
- 关节速度上限：0.05 rad/s。
- 输入滤波：0.35。
- max_joint_step：0.02 rad。
- 位置目标领先上限：0.01 m。
- 姿态目标领先上限：0.1 rad。
- 最小/最大阻尼：0.005 / 0.15。
- 奇异值阈值：0.05。
- 微分步长上限：0.01 rad。

这些是初次验证的小幅设置，不是已通过现场辨识或安全认证的参数。

若操作者位于基座 +X 一侧面向机器人，输入方向约定为 X→机器人 +Y、Y→+Z、Z→−X。实际站位不同则重新核对，不能直接大幅运动。TCP 填实际工具相对求解末端 Link6 的变换；只有确认空法兰目标点与求解末端一致时才可填全零。不能拿厂商工具编号代替几何变换。未核对前不勾选输入方向/TCP 确认框。

数据记录保留 arm.position、arm.position_target、quest.right_pose、quest.right_hold，无图像。先不录制，诊断日志保持开启。

### Quest 连接与首次跟随

USB 连接同一主机并允许调试，另一个终端执行：

```bash
adb devices
adb reverse tcp:8000 tcp:8000
```

头显使用匹配当前协议的 tracking 应用，TCP、localhost、8000，开启头部和手柄数据，使用右手柄。公开事件流为 v3 快照；电脑接收器与 Web 需配套版本，头显发送协议不用为这次快照修改。

网页检查、保存、启动 → 连接输入 → 头显连接推流 → 确认 Quest 新鲜输入与 CR5 反馈 → 准备设备。右手柄静止、grip 先松开，再按下，等待重锚成功。

保持 grip，先做很小的单轴平移，确认方向；松开验证按住模式停止，再分别验证其他平移和小角度转腕。重锚失败时检查原因，不通过放宽超时或反复按键强行继续。实体急停应保持可操作。

所有项目正常后才能考虑持续跟随：停止工作站，将使能改为“持续跟随 · 无按住使能信号”，保存重启。此时按 grip 开始后松开仍跟随，必须用 Web 暂停/停止。已保存为空字符串的持续跟随配置需要部署本次空值修复，旧进程不会自动生效。

## 结束与验收记录

按“暂停遥操 → 停止工作站 → 确认实际失能”结束，再退出 Web。记录实际设备、固件、限位、负载、TCP、关节方向和各阶段结果，保留诊断日志。不把软件回归或端口连通当作真机验收通过。

本手册没有在编写过程中连接/使能/移动真实机器人；当前仍需现场完成固件、ServoJ 参数、停止/断网、工具标定和长稳验收。
