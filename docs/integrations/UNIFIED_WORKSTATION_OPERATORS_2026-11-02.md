# 公共工作站统一操作（2026-11-02）

Quest3、Web 键盘、Vader 的操作进入同一个工作站操作接口，作用于当前运行的工作站及其机器人，不按机器人品牌分支。以下定义替代此前公共工作站的 Z/C、Y/X 等默认分配；旧独立 Profile 和终端工具不作为这套公共工作站的控制入口。

## 当前按键

- 开始遥操、重新建立跟随零点；策略/回放运行时人工接管；保持按住可提供跟随使能：Quest3 **右 grip**，键盘 **S**，Vader **M3**。
- 普通人工操作时开始录制；人工接管策略/回放之后交还控制：Quest3 **右 A**，键盘 **A**，Vader **A**。它不会在交还控制时顺带新建录制。
- 结束当前录制并保存：Quest3 **右 B**，键盘 **B**，Vader **B**。保存不等于暂停遥操。
- 丢弃正在录制的本段：Quest3 **右摇杆按下**，键盘 **N**，Vader **右摇杆按下（R3）**。先排空并关闭当前写入器，再删除本段目录；不会删除此前已保存的段。无当前录制时不删除任何文件。
- 停止跟随并直接回工作位：Quest3 **左 X**，键盘 **A+N 同时按住**，Vader **X**。录制中拒绝回位；先结束保存或丢弃。

键盘 A/N 单键在松开时执行，给 A+N 组合留出判定机会。组合键触发一次回位，释放任一键不会再补发录制或丢弃。其他旧键位没有注册为公共工作站快捷键。Vader M2 仍切换摇杆平移/旋转；LT 精细倍率、RT 夹爪和摇杆轴方向保留。

## 页面与操作顺序

在 Web「工作站」完成设备与控制映射配置，保存并启动，连接输入，按设备要求完成准备。在「检查与运行 → 运行控制」勾选「启用本页键盘控制」才能使用键盘；页面需要保持焦点。输入框、文本区、下拉框及文字编辑期间不执行快捷键。键盘失焦、切换标签页、取消启用或离开工作站页面会解除键盘 hold；网络中断后，键盘心跳最多 350 ms 失效。无需启动原来的采集/策略键盘节点。

右 grip / M3 首次连接时已经按住不自动启动，需要先松开再按；持续按住不重复请求。键盘忽略系统按键重复。每次有效开始动作进入有确认/回滚的重锚流程，所有控制映射确认后才进入人工遥操；即使已经 ACTIVE 也会重新建立跟随零点。Quest 裸手捏合不会启动工作站。

右 grip、M3 与键盘 S 是公共附加跟随使能，和控制绑定声明的按住信号取或；硬件使能按原始样本时间最多保留 250 ms，不因旧缓存被新帧携带而刷新。原有 `left_hold` / `right_hold` / `hold_to_control` 绑定继续有效。绑定没有 hold 时，仍按“持续跟随”工作，松开启动键不关闭整个工作站。全局暂停使用 Web「暂停遥操」。

Web 开始按钮也走相同的 `teleop_start`，提供交还策略/回放、直接回工作位与丢弃本段按钮。运行状态显示当前人工、策略、回放或回位控制，以及可交还的来源和错误。公共运行诊断记录 operator_request/result、operator_hold（变化/超时）、input_operation、work_position 和异常。

## 策略/回放的接管与交还

公共服务维护人工与自动控制的写入状态。策略或回放运行期间，普通遥操输入不能直接写设备，必须先用开始键人工接管。

接管时暂停策略/回放下发，保存交还来源，重置人工跟随基准。策略保留预测器，但丢弃接管前的待完成预测与动作分段；即使旧计算稍后返回也不会下发。按 A 交还时先确认当前观测的新预测，再提交控制权。回放保留下一帧游标，按当前实测位置重锚 offset 后继续，每帧使用当前提交时间，不突发追赶暂停期间的帧。

`POST /api/v2/sessions/{sid}/replay/start` 支持 `{frozen_resolved, actions, hz}` 连续回放（1–200 Hz，最多 100000 帧）。冻结的 feature/geometry 必须与当前工作站一致。原有 replay/step 仍为单步调试接口，自动控制或人工接管有待交还来源时拒绝插入单步。暂停保留自动控制与游标；接管前的暂停状态会在交还时恢复，需显式点击“继续策略／回放”才续跑。停止、急停、复位和回工作位清理交还关系。

公共工作站还在 Runtime.submit 分发前安装所有权检查，验证 producer/token/epoch、期限和资源，冻结期间拒绝运动；独立 Runtime 默认兼容行为不变。完整协议见 [HITL 对齐说明](WORKSTATION_HITL_ASTRAL_ALIGNMENT_2026-11-02.md)。

## 工作位配置

「遥操作设置 → 直接回工作位」按设备启用目标，填写各关节位置和插补速度，再保存新版本。所有参与设备的目标、维度、有限值、关节限位、速度和反馈先检查，再停止跟随并开始运动。未配置时明确报错，不自动把零位或某个品牌的默认姿态当成工作位。

配置保存在 `metadata.operator_control.work_positions`（组件 id → 关节数组）与 `work_speed`。单位与设备关节声明一致（如 rad、m 或 ratio），默认速度 .15 关节单位/s，上限 1，并受声明的 max_velocity 限制。不同设备用同一进度完成直线关节插补，故障、反馈失效、超时、暂停或停止会中断。调度停顿后单次只推进最多 100 ms 的轨迹，避免追赶时间造成目标大跳变。到位后暂停遥操；再次开始才恢复人工跟随。

这是直接关节插补，不经过旧 Astral/Nero 的途径点，不进行环境碰撞规划，也不等于旧原生驱动的多段工作位命令。真实部署需要填写适合现场的目标；本轮没有进行实机验收。

## 配置迁移和部署

Vader 描述符、运行时默认映射与实机输入覆盖示例同步为 M3/A/B/R3/X，默认 hold 改为 M3。页面和公共服务能识别此前发行的完整默认 START/B/Y/X、Z/B/Y/X、Z/C/Y/X 映射并升级；原 M1 默认 hold 一并改为 M3。真正的自定义映射保留，需自行核对。

加载旧配置后如发生迁移，页面要求保存新版本；不会拿旧编译哈希静默启动。Quest 增加左右按键采样端口，也会改变依赖快照，升级后应检查并重新保存工作站配置。更新后重启 Web 与它托管的 Quest 输入接收进程，刷新页面。APK 原有按键报文不变。

Quest 接收器将 trigger、grip、摇杆和六个按键位作为一条带 epoch/序号/时间和坐标系的 `controller_state` 原子事件发布，避免 newest-value 队列中多个同批消息互相覆盖。旧 pose/grip/trigger/landmarks 事件仍可解析；完整离散按键需要新版接收器。即使只选左手或右手运动，也会接收另一只手柄的操作按键，未选择手的位姿不进入运动映射。自定义 input_topic 需保留 `{side}` 占位符才能接收两侧操作键。

公共只读状态见 session state 的 `operator`。操作接口为 `POST .../operator/action`，载荷 `{action,request_id}`；动作包含 teleop_start、teleop_pause、record_or_release、record_stop、record_discard、workpos。`POST .../operator/hold` 载荷 `{client_id,held,sequence}` 用于页面心跳，递增序号防止松开后迟到的旧按住消息重新打开 hold；已完成的操作请求有有界去重，同一 id 不可换动作。

## 验证记录

覆盖 Quest 左右按键、初始按住、重复/过期事件、只选择单手运动时的操作键，Vader 的默认/自定义映射，键盘单键/组合键/旧键位与焦点清理；公共服务验证录制保存、丢弃隔离、回位插补、录制保护、反馈丢失、调度停顿、暂停取消、操作去重、策略旧预测隔离与交还后重新观测、回放游标保存和人工/自动写入隔离。Edge 验证页面工作位表单、S/A/B/N、A+N、输入框保护和开始/暂停/停止。最终回归数量记入 Changelog。

尚未进行实体 Quest3/Vader、真实机器人、真实模型服务和 ROS launch 的现场验收。软件测试使用 fake 设备、受控预测器和本地浏览器。

无 Web 的 `ControlHost` 提供可选 `operator_action` 委托接口，宿主可注入同一个操作协调器。默认轻量宿主没有模型/录制管理器时，不会凭空提供完整接管交还和段管理；本次完整操作验收针对公共 Web 工作站服务。
