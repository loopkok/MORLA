# 公共工作站 HITL 与 astral_ws 对齐（2026-11-02）

本次对齐的是接管协议、失败回滚、回放重锚和暂停上下文，并增加公共工作站的网关所有权检查。参考桌面 `astral/astral_ws/src/astral_policy_inference/` 的 `node.py`（_cmd_takeover / _poll_takeover / _abort_takeover / _cmd_release）、`controller.py`（interrupted 状态）和 `replay.py`（PlaybackSession.reanchor）。不是把 Astral 品牌节点复制到每个机器人驱动。

## 接管与确认

右 grip / S / M3 和 Web「开始遥操」调用同一个操作。公共工作站先检查绑定输入和设备反馈的新鲜性、维度及有限值，然后冻结人工/策略/回放输出、退役旧控制 epoch。设备已经 ACTIVE 时保留使能状态；需要激活时，等待 Runtime 激活操作确认完成，之后重新采样实际姿态和输入，不能把 accepted/DISPATCHED 当作完成。

每条配置的控制映射使用独立的待提交控制器建立基准。笛卡尔控制器用实测关节做 FK，并记录当前输入位姿作为增量零点；jog 用当前 FK 初始化积分目标，重锚阶段不求解或下发运动。CR5 在它自己的 FK/IK 工作线程完成这一动作后返回明确 ACK，清掉旧代次结果和滤波残留。同步标量/夹爪/手重定向映射以声明过的同步初始化检查确认，其他注册插件需提供明确的 reanchor 确认接口，不能靠有缓存输出冒充初始化完成。

所有映射确认后再次检查输入 epoch、源坐标系、样本时效、设备反馈及姿态变化，再原子安装这些控制器、签发新 epoch 并进入 HUMAN。下一帧保留已确认的绑定身份，不会因为 identity 变化把刚建立的零点再次清除。普通输入在 pending 阶段不能下发。

默认整个切换的期限为 3 秒，输入仍遵守每条 binding 的 max_age_ms。控制器创建/FK/初始化和剩余回放范围检查在有界后台工作线程执行，页面与停止操作不等待求解；完成状态由工作站 tick 推进。

## 回滚与中断

任意一条映射失败、输入断开/换 epoch/换坐标系、反馈失效或超时，都不会提交 HUMAN。待提交控制器被退役并独立关闭，晚到的 ACK 不能替换当前控制器，也不能恢复写入权限。

在设备仍正常、反馈仍新鲜的情况下，失败会恢复原来运行或暂停的策略/回放，并使用新的控制 epoch。回滚策略时重新获取观测，不复用失效预测；回滚回放保留原游标和偏移。若设备故障或无法安全恢复，保持输出关闭并报告 rollback_failed，不声称自动恢复成功。

交还策略前先用当前反馈/图像获得并校验一份新预测，确认后才把写入权限交回策略；首次预测失败、过期或超时，仍保留 HUMAN 及可再次交还的上下文。旧的后台预测即使返回，也没有本次控制 epoch，无法下发。

切换过程中暂停、急停、停止和故障复位可以取消切换，其他运动/接管动作被拒绝。取消会退役本次异步结果；设备激活若迟到，仍由 Runtime 的操作代次机制撤销。停止、急停、复位和回工作位会清理交还上下文。

## 回放交还与暂停恢复

回放保留下一帧游标。交还时按动作块的关节映射构造：`offset = 当前实测动作位置 - 下一帧原始回放目标`，之后发送 `原始目标 + offset`，不累计叠加旧 offset。

例如下一帧原始关节目标为 0.2 rad，人工操作后的实测为 0.8 rad，offset 为 0.6 rad；续播首目标为 0.8 rad，原来后续的 0.3 rad 变为 0.9 rad。不会再把首目标直接回拉到 0.2 rad。所有剩余目标都要满足当前关节限位；不满足时交还失败并保留人工控制，不静默裁剪轨迹。

接管前的 activity 和 paused 单独保存在 interrupted 中。在 HUMAN 中重复重定零点不会覆盖它。交还时：

- 原来运行的策略：确认当前观测的新预测后继续。
- 原来运行的回放：按实测重锚后继续剩余帧。
- 原来已暂停的策略/回放：恢复为已暂停，保持当前姿态，不自动续跑。

Web「暂停遥操」保留自动控制对象、回放游标和暂停上下文；新增「继续策略／回放」执行显式恢复。S / grip / M3 在自动控制已暂停时仍表示人工接管，不充当自动续跑快捷键。

## 公共命令入口

公共工作站启动时给自己的 RuntimeSession 安装 command_guard。它在 Runtime.submit 的设备分发之前检查冻结/暂停状态、当前 producer、token、epoch、租约期限及资源范围。切换中不允许任何运动写入；错误 owner、过期代次和超期许可直接拒绝，不因为旧请求被拒绝而停止合法的新 owner。回放和工作位循环按当前所有者续期。

这是公共工作站会话的强制检查，不再只依赖 service.ingest 的分支互斥。旧会话保存的 Runtime 对象也不能借新会话的许可恢复下发。独立创建且没有安装 guard 的 RuntimeSession 保留原来的兼容契约；直接绕过 Runtime 调用 SDK 或发布原生驱动话题仍不属于工作站仲裁范围。

## 状态、日志与部署

session state 的 operator 增加 paused、interrupted 和 transition（request_id / kind / phase / status / acks / error）。Web 显示确认进度、提交/回滚状态，pending 时保留暂停、急停与停止入口。诊断日志记录请求、逐映射 ACK、输入身份与反馈种子、提交、失败回滚和取消。

操作键位保持统一分配不变。更新后重启 Web 和输入进程、刷新页面；如果组件依赖快照变化，重新检查并保存工作站配置再启动。现有接管前旧的“仅暂停策略并重置控制器”“回放只保留游标”的行为被本次实现替代。
