# CR5 MuJoCo 与统一 Web 实施日志

日期：2026-11-01，Asia/Shanghai。起点：`9272b7f`，分支 `main`。

## 需求与实现范围

CR5 已有驱动、URDF、本地 Pinocchio IK 和遥操绑定；手柄测试时出现 IK 不可达/限位失败。此次参考 Nero/Astral 的模型资源与仿真反馈方式，为 CR5 建立可独立调试的 MuJoCo 环境，接入项目当前统一组合运行路径和 Web。没有修改 IK 数学算法，也没有将原台架故障记为已修复。

- `src/robot_description/scripts/make_cr5_mjcf.py` 从版本化 CR5 URDF 生成 `mjcf/cr5/cr5.xml`，复用现有视觉网格，保留六轴顺序、轴向、关节原点、限位、质量、惯量及 Link6 末端。
- `composable_scene.py` 注册 CR5 模型和 base/flange；设备 descriptor 启用 sim 并显式映射 joint1..joint6。与 Nero/Astral 共用场景拼接和 MuJoCo 运行后端，没有新增实体 CR5 写入路径。
- `MujocoDeviceSession` 支持从组件参数读取 `initial_positions`，检查维度、有限值和关节限位后同时设置初始关节与控制目标。CR5 模板使用 `[0,-0.5,1,-0.5,1,0]` rad，避开全零伸直位；反馈继续标记 simulation/synthetic，不能当作实测硬件数据。
- CR5 异步 Cartesian 控制器接受 sim 后端，使用现有 Pinocchio 求解器、TCP/相对输入映射和限速。新增 sim 可选 Python 依赖与 Web launch 的包依赖。
- `config/quest_right.sim.yaml` 组合 CR5 sim、Quest 输入和场景相机；Quest 默认 fake，可独立选择 real。`launch/cr5_sim.launch.py` 启动统一 session host 和 Web，默认不激活运动。
- Web「组合配置」增加模板加载、相机预览和刷新页面后恢复当前保存会话。模板加载沿用已有配置的版本号继续保存；前端 `web/dist` 已重建并随提交更新。
- 新增 `GET /api/v2/templates/cr5-sim` 和 `GET /api/v2/sessions/{session_id}/cameras/{camera_id}/frame`；预览返回 JPEG 且禁止缓存，未知/非相机为 404，尚无有效图像为 503。会话 state 补充 assembly_id/revision 供恢复配置。

## 仿真数值问题与处理

初始调试发现：参考位置伺服 `kp=1200`、`kv=120` 在 2 ms 显式积分下，CR5 腕部持续振荡并触及 ±300 力矩限制，不能稳定跟踪目标。共享拼接场景及 CR5 独立模型改用 `implicitfast` 积分后，同一目标稳定收敛。

离线 6 s 仿真，目标 `[0.1,-0.45,0.95,-0.45,1.05,0.05]` rad，得到约 `[0.1,-0.45722419,0.95382243,-0.45003308,1.04999807,0.04999999]` rad；关节速度降到约 `1e-14` rad/s。位置伺服无重力前馈，存在小的静态重力误差。本次采用参考伺服，未声称匹配实体控制器参数。共享积分器的变化影响其他组合场景，已对现有 Nero/Astral 拼接与运行测试回归。

## 使用与未执行项

构建并 source ROS 工作区后：

```bash
ros2 launch morla_cr5_driver cr5_sim.launch.py
# CR5 仍是 sim；只将 Quest 输入改为实体输入：
ros2 launch morla_cr5_driver cr5_sim.launch.py input_backend:=real
```
