# CR5 MuJoCo 与统一 Web 实施日志

日期：2026-11-01，Asia/Shanghai。起点：`9272b7f`，分支 `main`。

## 需求与实现范围

CR5 已有驱动、URDF、本地 Pinocchio IK 和遥操绑定；手柄测试时出现 IK 不可达/限位失败。此次参考 Nero/Astral 的模型资源与仿真反馈方式，为 CR5 建立可独立调试的 MuJoCo 环境，接入项目当前统一组合运行路径和 Web。没有修改 IK 数学算法，也没有将原台架故障记为已修复。

- `src/robot_description/scripts/make_cr5_mjcf.py` 从版本化 CR5 URDF 生成 `mjcf/cr5/cr5.xml`，复用现有视觉网格，保留六轴顺序、轴向、关节原点、限位、质量、惯量及 Link6 末端。
- `composable_scene.py` 注册 CR5 模型和 base/flange；设备 descriptor 启用 sim 并显式映射 joint1..joint6。与 Nero/Astral 共用场景拼接和 MuJoCo 运行后端，没有新增实体 CR5 写入路径。
- `MujocoDeviceSession` 支持从组件参数读取 `initial_positions`，检查维度、有限值和关节限位后同时设置初始关节与控制目标。CR5 模板使用 `[0,0,π/2,0,-π/2,0]` rad（J3 +90°、J5 −90°，其余归零；初版为 `[0,-0.5,1,-0.5,1,0]`，见文末「腕部 IK 修复」）；反馈继续标记 simulation/synthetic，不能当作实测硬件数据。
- CR5 异步 Cartesian 控制器接受 sim 后端，使用现有 Pinocchio 求解器、TCP/相对输入映射和限速。新增 sim 可选 Python 依赖与 Web launch 的包依赖。
- `config/quest.sim.yaml` 组合 CR5 sim、Quest 输入和场景相机；Quest 默认 fake，可独立选择 real。`launch/cr5_sim.launch.py` 启动统一 session host 和 Web，默认不激活运动。
- Web「组合配置」增加模板加载、相机预览和刷新页面后恢复当前保存会话。模板加载沿用已有配置的版本号继续保存；前端 `web/dist` 已重建并随提交更新。
- 新增 `GET /api/v2/templates/cr5-sim` 和 `GET /api/v2/sessions/{session_id}/cameras/{camera_id}/frame`；预览返回 JPEG 且禁止缓存，未知/非相机为 404，尚无有效图像为 503。会话 state 补充 assembly_id/revision 供恢复配置。

## 仿真数值问题与处理

初始调试发现：参考位置伺服 `kp=1200`、`kv=120` 在 2 ms 显式积分下，CR5 腕部持续振荡并触及 ±300 力矩限制，不能稳定跟踪目标。共享拼接场景及 CR5 独立模型改用 `implicitfast` 积分后，同一目标稳定收敛。

离线 6 s 仿真，目标 `[0.1,-0.45,0.95,-0.45,1.05,0.05]` rad，得到约 `[0.1,-0.45722419,0.95382243,-0.45003308,1.04999807,0.04999999]` rad；关节速度降到约 `1e-14` rad/s。位置伺服无重力前馈，存在小的静态重力误差。本次采用参考伺服，未声称匹配实体控制器参数。共享积分器的变化影响其他组合场景，已对现有 Nero/Astral 拼接与运行测试回归。

## 使用与未执行项

```bash
ros2 launch morla_cr5_driver cr5_sim.launch.py
# CR5 仍是 sim；只将 Quest 输入改为实体输入（real 必须带 device_id）：
cp src/robots/dobot/morla_cr5_driver/config/quest-input.real.example.yaml /tmp/quest-input.real.yaml
```

单独的 `input_backend:=real` 不够：编译器要求 real 后端显式 `device_id`，会话在启动前就会报 `real backend requires explicit device_id`。

浏览器打开 `http://127.0.0.1:8080` →「组合配置」，查看仿真画面与健康信息，显式激活运动许可。已有统一 Web 服务（`tools/start_morla_web.sh`）在启动时会把这份模板写成一条普通保存配置 `cr5_quest_sim`，页面「打开已保存配置」选它 → 校验预览 → 保存下一版本 → 启动 → 连接输入 → 激活；实体 Quest 需把 quest 后端改为 real 并填「设备标识」，再保存启动。详细配置见 CR5 包 README。

## 腕部 IK 修复（2026-11-01 追加）

实体 Quest 捏合测试数据复现后确认，不是映射方向错，而是 wrist 旋转下的局部信任域太窄，且模板起始位形条件数差：

- 位置映射正确：手位移 20 cm 在 `position_scale: 0.25` 下产生 4.9 cm 机器人位移，方向为 base −X；IK 往返误差 < 0.2 mm。
- 旋转不可用：旧位形下工具绕 base z 只转 −5° 就 `stalled_or_unreachable`（残差 1.33°），±10° 在 z 上失败；+5° 已需要 15.7° 关节行程，而单次求解信任域是 ±0.3 rad（17.2°）。旧位形 Jacobian 最小奇异值 0.023（cond 86），现位形 0.15（cond 14）。
- 失败代价被放大：位姿目标是从锚点重算的绝对目标，求解失败即整帧丢弃，机械臂彻底冻结（实测腕转 30° 后臂动 0.0°，随后 20 cm 手推位移 0.000 m）。
- 修法：`IKSolver` 增加 `retry_trust` 阶梯（位姿 `0.3 → 0.6 → 1.2` rad，jog 仍只 `0.3`，因为 `jog_blocked` 依赖被拒绝的求解结果）；模板起始位形按操作员要求改为 `[0,0,π/2,0,-π/2,0]`（J3 +90°、J5 −90°，其余归零，σ_min 0.209 / cond 8.8），`position_scale` 0.25 → 0.8、`max_joint_velocity` 0.3 → 1.0 rad/s（原为 17°/s，明显发粘）。
- 验证：`morla_cr5_driver` 21 passed（含新增 `test_tool_rotation_beyond_one_trust_window_is_recovered`，直接以模板位形为基准：x/z 轴 ±30° 需阶梯第二级 0.6 rad、y 轴需 1.2 rad 才解出，单窗口 jog 仍拒绝）；离线整链（`create_controller` + 模板参数）从该位形出发，腕转 ±30°、手推 15 cm 前后左右均产生关节运动（绕输入 z 腕转 30° 干净地只动 J6 −30°，绕输入 y 动 J5 +29.8°）。注意：pytest 必须保留 ROS 的 `PYTHONPATH`，直接覆盖会让用户级 cmeel Pinocchio 抢先加载并 `undefined symbol` 跳过全部 IK 用例。
- 未处理：`binding.deadman` 编译进配置但运行时不生效（无代码读取）；旧保存配置 `cr5_quest_sim` 若不重新保存，仍带旧位形与旧参数。
