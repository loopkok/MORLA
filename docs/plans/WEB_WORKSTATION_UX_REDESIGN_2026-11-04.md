初稿：2026-11-04；本次修订：2026-11-09（Asia/Shanghai）。源码核查基线：`main` / `d3e0ab3`。

状态：**六页重构与功能实施已完成，软件回归通过，现场场景待复验**。40 项前端测试、28 项公共工作站测试及 FR3/CR5 fake 浏览器闭环通过，构建产物已更新。详见[验收记录](../testing/WEB_WORKSTATION_UX_ACCEPTANCE_2026-11-09.md)。下文“实施前基线核查”保留改造前证据，页面规范作为实现契约；未勾选项表示尚未完整复验的场景。

本次依据当前前端、v2 API、编译器、设备 descriptor 和 CR5/FR3 控制器实施；验证使用隔离 fake 会话，未重新执行历史硬件验收。主机已保存装配的 revision 与参数只作为历史案例，不代表本地配置存储状态。

- [2026-11-09 参数清理记录](../integrations/CHANGE_LOG_2026-11-09.md)：设备/绑定上限、无效字段、记录字段及保存版本升级。

## 目标与实施边界

- 建立设备选型、连接与标定、遥操配置、数据记录、检查、运行的完整流程。
- 采用接近 macOS 工具软件的中性色、分栏编辑和统一控件层次，适配桌面宽屏与约 650px 宽的预览窗口。
- 添加多台设备时，设备列表增长，参数编辑区域保持稳定。
- 每个用户操作都有提交、执行和最终结果反馈，失败能定位到设备或字段。
- 使用现有 `/api/v2` 接口、保存格式、控制器和设备能力。改造前端页面组织、调用编排、状态解释及视觉。
- 本计划不包含修改驱动、SDK、IK、运动门控、公共工作站控制权逻辑或增加后端接口。发现现有接口无法提供某项数据时记录缺口，界面显示“暂无数据”，不推测数值或硬件状态。
- 已有配置中的端口、显式参数、兼容字段、自定义门控和数据通道均保留。浏览表单、切换页面和展开面板不得改变配置。

## 实施前基线核查

### 已完成能力与仍待改造部分

- 已有五个导航页：设备选型、安装与标定、遥操作设置、数据记录、检查与运行。六页拆分、右侧设备列表、左侧单设备编辑和固定操作区尚未实现。
- `/components` 已包含设备和控制器；`/templates` 已动态提供安装可用的预设。显示名、字段可见性、连接字段、后端/条件过滤、首选控制器与绑定预设已经读取 descriptor。后续组件必须复用这条路径，不维护新的机器人白名单。
- FR3 已包含 fake/sim/real 声明、专属 Cartesian 控制器、Quest 预设和共享 MuJoCo 接入。能力可选不等于实机验收通过；描述符验证等级和现场结果分别展示。
- CR5 已增加设备级速度/领先上限；绑定 `command_lead_rad` 已可编辑。CR5、EPG、LoopHand 的部分无效设备参数已从 schema 删除，通用字段标签中的核对项已加“仅记录”。但页面直接写出的身份、停止测试、输入方向/TCP 复选框仍未统一这段说明，属于本轮待补齐内容。
- 已有刷新恢复活动会话、500ms 状态轮询、控制权 transition 展示，以及忙碌/交接期间仍可用的暂停、急停和停止。下一轮保留这些能力，补操作终态跟踪、顺序轮询和跨页问题保留。
- 已有 IK 嵌套报告展开与空报告过滤、录制完整性失败提示、诊断日志查看/下载、仿真视角交互、手机配对和回工作位。拆分运行页时逐项迁移。

### 页面和状态

`src/common/morla_web_manager/web/src/components/ComposableTab.tsx` 集中承担设备编辑、参数过滤、控制链、保存、检查、运行、轮询和诊断。后续拆分时保留顶层状态所有权，避免不同页面各保存一份装配副本。

当前主要状态包括 `assembly`、`deployment`、`resolved`、`savedRevision`、`savedHash`、`session`、`preflight`、`busy` 和单条 `message`。切换导航会清除消息。多个请求共用一个 `busy`，操作提交后常显示笼统的“已提交”。

当前 `workcell.css` 主要采用纵向卡片、三列表单、大量折叠区和黄褐色强调。设备与控制链增加后，页面高度持续增长。

已核查的交互缺口：`check()` 只调用 compile，依赖检查另行调用 preflight；两个结果尚未统一。`backend()` 切出 real 时删除该实例的 deployment 项；`updateBinding()` 会重建绑定参数。重构需为这两类变更提供预览、取消与保留方案。保存/检查请求尚无草稿代次保护；`operate()` 仍主要提示“已提交”，不能替代操作终态。

### 已有接口与真实语义

接口定义位于 `src/common/morla_web_manager/morla_web_manager/composable_api.py`，行为位于同目录 `composable_service.py`。以下路径均带 `/api/v2` 前缀。

- `GET /components` 提供设备与控制器 descriptor、schema、defaults、web 元数据和能力声明。
- `GET /templates`、`GET /templates/{template_id}` 提供可发现预设及内容。沿用已有模板 ID 和按 `assembly_id` 恢复选择的行为；资源缺失和目录请求失败要有明确反馈。
- `GET /active-session` 返回活动会话或 JSON `null`；现有 request 已支持 `null` 和非 JSON 错误提示，抽取客户端时保留。
- `GET /assemblies`、`GET /assemblies/{assembly_id}/revisions/{revision}` 提供已保存配置。
- `POST /assemblies/compile` 编译并检查装配与部署配置，返回解析结果、诊断和特征契约。
- `POST /deployments/preflight` 内部也编译配置，返回 `compile_valid`、`device_probe_performed`、`preflight`、`status` 和 `resolved`。当前明确返回 `device_probe_performed: false`。
- `POST /assemblies` 保存配置版本，沿用 `expected_revision` 并发控制。
- `POST /sessions` 创建运行会话，可能建立设备连接。前端需明确提示真实设备连接的实际影响。
- `POST /sessions/{session_id}/operations` 提交 `connect_inputs`、`prepare`、`disarm`、`reset`、`estop`、`stop` 等操作。
- `GET /sessions/{session_id}/operations/{request_id}` 查询已经登记的异步操作。
- `GET /sessions/{session_id}/state` 获取运行状态及输入、设备、控制权、控制器、仿真、诊断等信息。
- `POST /sessions/{session_id}/operator/action` 提交公共工作站操作。开始遥操继续通过 `teleop_start` 发起。
- `POST /sessions/{session_id}/operator/hold` 接收键盘按住状态，沿用现有 `OperatorKeyboard` 行为。
- 录制、策略、回放、仿真和诊断沿用当前页面已有对应接口，不在本计划里创建替代接口。

`prepare` 的实际执行对象为设备适配器。CR5 使用的 `CachedActuatorAdapter.prepare()` 检查新鲜反馈，`activate()` 才继续调用 transport 激活。其他设备的准备语义以对应适配器返回为准。前端使用“设备就绪检查”，并在 CR5 的说明中解释反馈检查。

`connect_inputs` 返回成功表示接收管理器启动成功；还需结合 `inputs.connected` 和 `inputs.fresh` 区分设备连接与有效输入。该分支直接返回结果，不保证出现在 operations 查询列表中。

开始遥操可能经过异步重锚和激活。前端依据 `operator.transition` 和最终运行状态展示进度，不将 HTTP 200 当成遥操已开始。

冷机 EPG 在使能前可能没有位置数值，现有 handoff 先检查健康与新鲜度，激活后再检查位置。UI 不得新增“全部位置数组齐全才允许开始遥操”的前置门禁，也不能把空位置自动解释为设备故障。

启动时后端重新编译已保存配置，并比较请求的 `assembly_hash` 及完整 saved resolved。仅比对前端 hash 不能证明依赖仍然一致；出现 `preview/installed dependency hash changed` 时引导检查并保存新 revision，不修改历史快照或绕过校验。

## 信息架构与导航

导航由当前五页调整为以下六页，不显示编号；硬件连接从设备卡片移到“连接与标定”，“检查与运行”拆成两个页面。

1. 设备选型
2. 连接与标定
3. 遥操配置
4. 数据记录
5. 检查
6. 运行

页面之间允许来回编辑。导航显示“待配置”“有问题”“已检查”等文本或小图标。运行会话存在时，沿用当前编辑锁定规则，并在锁定区域说明原因。

顶部工具栏显示工作站名称、未保存状态、保存版本、运行状态。打开、保存、另存为、导入、导出、载入预设收进统一工具区。另存为的具体行为通过现有保存接口完成，不能覆盖原配置版本。

底部主要操作与当前页面相关，例如“继续：连接与标定”。主操作区域固定可见，避免滚动到长页面末尾。

## 视觉和布局规范

### 色彩与控件

- 默认采用中性深灰外壳和略浅的面板，选择与主按钮使用一种低饱和蓝。
- 文字建立主要、次要、辅助三档对比度。状态由文字、图标和颜色共同表达。
- 故障和急停采用红色，警告采用低面积的琥珀色。移除大面积彩色容器和渐变。
- 字体使用 `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。数值使用等宽数字。
- 间距以 4/8px 为基础，面板圆角约 10px，输入框约 6px，常用控件高度约 34–36px。
- 聚焦轮廓、键盘导航、选中状态、禁用原因统一。动画仅用于面板切换和反馈，尊重减少动态效果偏好。
- 不添加仿造系统窗口控制的红黄绿装饰按钮。

### 区域滚动和响应式

- 顶部工具栏、流程导航和底部主要操作保留在可见区域。
- 宽屏采用左编辑区与右设备面板，右面板约 280–320px，左编辑区占剩余空间。
- 中等宽度缩小右面板，字段通常为两列。
- 约 650px 宽度时，右侧面板改为“设备列表”抽屉，选中设备名称固定显示；编辑区按一至两列自适应。
- 表单内部避免再出现多层固定高度滚动。设备列表和编辑区可各自滚动，弹窗仅正文滚动。
- 不依赖 hover 才能发现操作，窄屏与触屏均能使用。

## 页面逐项修改

### 设备选型

右侧设备面板包括“已添加”和“设备库”两个分段。

- 已添加列表按输入、机械臂、末端和相机组织，显示名称、侧别、运行后端和配置缺项。
- 设备库支持分类与搜索，显示已声明的可用后端，禁用项解释原因。
- 添加后自动选中新设备并聚焦名称或第一个必要字段。
- 左侧只渲染当前设备的参数，设备切换前后保留未保存编辑。
- 左侧上方为通用设置，下方为设备专用设置。硬件地址与连接身份迁入下一页面。
- 参数分段以设备实际支持的功能命名，例如“关节配置”“手部处理”“输入接收”；没有对应字段时不生成空分段。字段集合继续由 `configuration_schema` 与 `web.fields/connection_fields/field_backends/field_conditions` 决定。新增插件未提供专门分组时使用通用 schema 表单。
- 显示参数的来源：插件默认、装配显式值、部署覆盖。设备合并优先级为 defaults → instance parameters → deployment parameters；运行时以本次编译返回的 resolved 为准。恢复默认应删除当前层显式值并显示下一层来源，不能把默认值批量写入保存配置。
- 仿真和真实设备的参数按当前后端显示。切换后端前检查已有部署信息，保留隐含值，避免清空用户连接参数。
- 删除设备前列出受影响的控制链、安装关系和记录通道，由用户确认。确认后按已有规则清理引用，选中相邻设备。
- 复制设备仅复制适用配置，生成独立实例 ID；设备身份和资源标识要求重新核对，避免无提示地指向同一真机。

### 连接与标定

进入时显示选型摘要与未完成项，直接作为页面顶部过渡区域。右侧继续复用设备列表，左侧编辑当前对象。

分段为“硬件连接”“安装关系”“坐标与标定”。

- 真实设备显示当前插件实际使用的连接字段、身份与共享驱动设置。Nero 的 CAN、CR5/FR3 的 IP、末端执行器的串口等分别显示。字段来自各自插件元数据。
- 仿真和测试设备显示后端说明及适用初始化设置，不显示空的网络连接表单。
- 安装关系以层级树显示世界、基座、机械臂、末端和相机。选择节点编辑父坐标系和安装变换。
- 位置按 X/Y/Z 分组，姿态按 Roll/Pitch/Yaw 分组，并固定显示单位。沿用现有四元数和矩阵转换函数。
- “坐标重合”作为明确按钮，显示其将写入的位姿；已有非零值需要确认覆盖。
- 标定记录、核对状态可编辑，不能自动勾选用户尚未完成的确认。身份、停止测试、运动学、输入方向/TCP 等记录项统一注明“仅记录”，并说明它们不替代真实探测、运动许可或验收；同时覆盖通用字段和直接渲染的 Check 文案。
- 协同控制组放在工作站级面板中，保持当前组定义与故障策略。
- 字段填全显示“配置完整”；只有读取运行结果后才能显示“已连接”。

### 遥操配置

页面主体命名为“遥操控制链”。每行关系显示“输入 → 控制模式 → 执行器”。

- 链列表展示设备名称、侧别、跟随方式、配置完整性，原始端口 ID 仅在技术详情中出现。
- 点击链的输入、模式或执行器节点，在同一参数编辑区选择与修改。
- 输入设备列表包含已添加且能通过某个控制器驱动该目标的输入，不能被当前控制模式提前锁死。
- 控制模式复用 catalog `controller_types` 与 `compatible()` 校验语义、维度、单位、目标插件/能力和 backend；复用 `web.control_family/ik_modes/preferred_controllers` 决定表单与默认模式。CR5、FR3 各自选择兼容控制器，未知品牌也可由声明接入。
- 切换 Quest/Vader 时，明确显示控制模式变更以及受影响参数。可复用的参数继续保留，需重新生成的参数给出变更摘要；取消时恢复整条链原值。
- 同时维护 source、target、controller、deadman、input_basis_id、parameters 的一致性，用一次状态更新提交，不出现中间无效绑定。
- 坐标映射、TCP、比例和限速作为控制链参数。求解与输入时效放在单独的参数分段，避免重复输入端口选择。
- 默认值复用 `pluginBindingDefaults()`：保留现有通用回退、controller defaults 和目标 `web.binding_presets` 的覆盖顺序。只在新建或用户确认切换控制链时应用，不以新默认值刷新已保存参数。
- FR3 当前 Quest 预设的 `input_rotation` 为 `[[-1,0,0],[0,0,-1],[0,1,0]]`；从 descriptor/模板加载，禁止在新页面复制一份常量。保留旧配置显式 `input_rotation` 和可选 `input_position_rotation`，用轴映射与单位说明帮助核对，不能擅自替换成 CR5 的基变换。
- CR5/FR3 的笛卡尔控制链增加上限来源摘要：设备 `max_velocity_rad_s` 与绑定 `max_joint_velocity`、设备 `max_command_lead_rad` 与绑定 `command_lead_rad` 分别显示，并依据当前已核查控制器语义显示两者取小后的配置约束。缺少可靠解析信息时显示“检查后查看”，不把该计算当成实测速度或全机器人通用规则。
- 设备上限默认在设备页编辑，已有部署覆盖在连接页显示并编辑，绑定上限在控制链编辑；摘要跳转到实际生效来源对应的字段。CR5 ServoJ 插值参数仍属于设备配置。FR3 的候选结果领先裁剪与 CR5 的积分种子限制不同，不宣称两者控制效果相同。
- FR3 descriptor 默认速度仍为 0.3 rad/s；主机 `fr3_quest_real` 曾保存为 1.0 是特定装配变更，不能据此提高新建配置或其他预设的默认速度。
- 跟随方式使用“持续跟随”和“按住跟随”；当前实际采用的源门控、工作站公共 hold 和键盘条件在链旁明确说明。
- 旧自定义门控显示“自定义”，允许查看和修改，加载时保留值。
- 工作站快捷键作为独立帮助面板，解释开始、暂停、接管、录制和回工作位，与控制链的位姿来源区分展示。
- 控制链之间切换保留当前参数、滚动位置和未保存状态。

### 数据记录

使用设备列表和通道配置面板，主区域展示记录对象摘要。

- 机器人状态、动作、相机按设备分组，每项使用含义清晰的名称和单位。
- “记录遥操输入”按实际控制链生成，并显示包含的通道。
- 额外采集按位姿、按键与摇杆、关键点分类；兼容端口仅在已选旧配置或主动查看技术详情时出现。
- 频率、动作来源与任务名称集中显示，避免同一设置在运行页重复配置。当前任务名是前端 `task` 状态并随录制请求提交，不擅自把它写入未定义的保存字段；运行页仍可编辑下一段任务名，录制期间沿用锁定。
- 独立诊断日志与数据集录制分别显示名称和状态。诊断日志默认设置保留，运行页提供紧凑摘要和详情入口。

### 检查

独立检查页包含摘要、检查项列表、问题列表和底部主要操作。

主要按钮为“执行检查”和“保存并进入运行”。保存草稿仍可通过顶部工具栏执行。

“执行检查”的调用策略如下。

1. 记录当前草稿代次，清除对应旧检查显示。
2. 调用 `POST /deployments/preflight`。该接口已包含配置编译，成功时直接使用其 `resolved`，避免再请求一次 compile。
3. 解析编译诊断、依赖结果、配置状态，映射成设备参数、控制链、安装声明、记录配置、运行依赖等展示项。
4. 编译失败时定位字段，依赖检查显示“未执行”。网络失败显示“检查未完成”。
5. 警告和失败分别展示。仅依据当前后端已有阻断条件决定是否允许继续，不能把所有警告升级为阻断。
6. 检查过程中草稿发生改变，返回结果标记为过期，不能用于启动新草稿。
7. “保存并进入运行”保存经过检查的同一份草稿，成功后切换运行页。保存失败保留编辑和检查结果，展示冲突或网络原因。
8. 插件摘要/依赖变更导致旧 revision 无法启动时，展示“检查并保存新版本”入口及差异摘要。新 revision 中更新 lockfile/hash，旧 revision 保持只读；不能自动重新启动。

每条问题包含严重程度、设备/控制链、字段、原因、修正入口和可展开的原始详情。明确显示检查不包含真机探测、实测标定或碰撞验收。

### 旧参数与配置升级

- 本次已删除的无效设备字段为：CR5 的 `command_timeout_s`、实例级 `max_step_rad`；EPG 的 `max_step_m`、`command_timeout_s`；LoopHand 的 `command_timeout_s`、`max_step_rad`。不重新把这些字段放回正常参数表单，也不把 CR5 绑定的有效步长参数一并删除。
- 旧实例参数可能被 `additionalProperties: false` 拒绝；旧 deployment 中同名键可能仍被合并却不生效。加载时保留原文并显示来源和兼容问题，不假装它们仍是有效旋钮。
- 对上述已核实无效字段提供明确的移除差异预览，经用户确认后在草稿中清理并重新检查/保存。对其他未知字段保留并展示后端诊断，不能按“当前表单没显示”批量删除。
- “仅记录”字段继续保存，不随无效字段清理删除。升级操作可取消，取消后原参数、标定和部署覆盖保持不变。

### 运行

运行页上方为状态总览，中部为数据与可视化，下方为固定操作栏。

状态总览分别显示会话、输入、设备和控制权，避免用一个绿色圆点代表全部状态。

主要操作随状态调整。

- 未创建会话时显示“初始化工作站”。
- 初始化流程进行中显示当前阶段与逐项结果。
- 设备和输入满足现有开始条件时显示“开始遥操”。
- 运行中显示“暂停遥操”，结束工作站保持可达。
- 有可复位故障时显示“复位故障”及原因。
- 急停按钮固定可见，沿用现有确认和调用语义，不能因普通请求忙碌而不可操作。

“初始化工作站”前端按现有接口编排。

1. 校验已保存版本和 assembly_hash 与当前草稿一致。
2. 涉及真实设备时展示连接影响确认，确认后调用 `/sessions`。
3. 创建成功后记录 session_id，查询 state。
4. 对适用输入调用 `connect_inputs`。接收服务结果与设备连接/输入有效性分开显示。
5. 调用 `prepare` 做设备就绪检查，跟踪返回的异步操作到终态。依据各适配器实际回执判定，保留冷机末端健康检查与位置反馈的区别。
6. 汇总输入和设备状态，显示下一步条件。等待外部 Quest 数据时，明确显示“接收服务已启动，等待输入”。
7. 初始化流程结束后由用户单独触发“开始遥操”。

连接失败保留会话和已成功步骤，提供针对失败步骤的重试。初始化流程超时显示“结果待确认”，查询会话后决定后续动作。不得因超时自动重新创建会话或自动激活设备。

运行数据使用已有接口能够证明的值。

- 输入显示接收进程状态、连接、有效性、当前模式及接口返回的错误。
- 设备显示 ready、reason、可用的关节反馈及单位。
- 控制链显示已有 IK 结果、残差、奇异性指标和报告更新时间。
- 控制权显示 HUMAN、策略、回放、暂停和交接阶段。
- 仿真画面、相机和本地 viewer 状态复用已有接口及组件。
- 日志和录制显示状态、目录、统计量和失败原因。
- 已有接口没有提供准确输入频率、网络时延或真实驱动使能位时显示“暂无数据”。不得从 ready 或 ACTIVE 推断这些值。

## 请求与状态管理

### 前端状态划分

- 配置状态由 ComposableTab 持有，包含 assembly、deployment、草稿代次、保存版本与解析结果。
- 编辑状态包含当前页面、选中设备、选中控制链、右面板展开状态与字段定位。
- 检查状态包含草稿代次、开始/结束时间、检查项和问题。
- 运行状态来自会话接口，UI 自己记录请求提交过程，服务端返回是最终事实来源。
- 通知与操作历史记录用户可见消息，不能替代运行状态。

### 异步操作

为请求建立统一记录，至少包括 requestId、操作类型、对象、阶段、开始时间、结果和错误详情。

- 发起前禁用同一操作的重复提交，按钮显示正在执行。
- 对已登记异步操作查询 operations/{request_id}；对直接返回结果的 connect_inputs 使用直接回执和 state；对 teleop_start 跟踪 operator.transition。
- 某类操作没有登记查询记录时，不把 404 一律当作设备失败。
- 使用单一会话轮询源，各视图订阅同一份状态。离开运行页后仍跟踪活动会话。
- 查询采用顺序调度，避免慢请求堆叠；页面失去焦点可降低展示轮询频率，键盘 hold 心跳保持原逻辑。
- 保留已有 `/active-session` 恢复：刷新后读取保存配置和状态，不重发开始动作。增加恢复中/恢复失败状态，避免恢复响应覆盖用户已开始编辑的新草稿。
- 配置请求使用 AbortController 和草稿代次防止迟到覆盖。取消浏览器请求仅意味着停止等待，不能显示成服务器操作已取消。
- 操作超时、断网和响应丢失优先重新查询；重试策略依据现有 request_id 语义逐类处理，禁止统一重放所有 POST。

## 反馈体系

- 字段错误紧邻输入框，显示名称、单位与可执行的修正提示。
- 普通成功用短暂 Toast，并更新持久页面状态。
- 执行中用按钮状态与进度面板，完成后保留结果摘要。
- 阻断性失败打开错误详情 Sheet，显示操作、对象、原因、修正入口和可复制的原始错误。

- 常见错误做可维护的翻译映射，未知错误保留原文，不编造建议。
- 轮询重复错误按会话与错误标识去重，断网只保留一条持续状态，恢复后更新。

## 完成定义
