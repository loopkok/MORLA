# MORLA 外部组件接入优化计划

制定日期 2026-11-18。源码基线 `e14d280`。本文记录实施顺序与验收条件。

## 实施结果

- 已实现标准 wheel 静态发现、资源读取、工厂来源匹配、目录诊断与冲突隔离。ament 和旧安装元数据的兼容路径仍可读取。
- 已实现具名端口角色、外部参数校验、Web 多路 JPEG 预览和结构化 HDF5 采集。通用 MuJoCo 场景以每个相机实例的首个图像端口生成一个视点。需要多个仿真视点或其他传感器模型时由设备插件提供仿真实现。
- [外部四设备插件](../../examples/external_components/README.md) 可复制到仓库外构建。`bash scripts/test_composable.sh --layer external` 在只加入公共组合式 Python 包的路径下构建并安装真实 wheel，验证预检、自定义夹爪目标、外部 IK 与模型文件、多路相机和 HDF5 落盘。该命令已加入 CI。
- Edge 使用临时 fake 工作站验证了两路预览切换和页面录制。已逐字节对比 CR5、FR3、MMK2、Quest→EPG、CR5+EPG 和 CR5+LoopHand 六份旧配置的完整 resolved 快照，结果与基线相同。
- 本地验证通过 278 项公共链路回归、229 项厂商包回归、25 项共享仿真回归和 48 项 Web 单元测试。外部 wheel 和采集回归在 HDF5 字段元数据变更后再次通过。TypeScript 与 Vite 生产构建已通过。
- 此轮验收依赖 fake 和仿真。ROS/DDS 与硬件的联调和停止行为仍由目标设备部署验收。原有 Profile 和厂商包可继续按当前安装方式使用。

## 交付目标

第三方在自己的仓库维护设备描述、适配器、可选控制器、模型资源和工作站模板。用户安装插件包后，MORLA 能发现设备，在 Web 中添加并配置实例，编译装配，运行支持的后端，并按所选端口完成预览或采集。接入另一个符合接口的厂商设备时，变更只涉及插件包和工作站配置。

- 设备已使用现有协议时，复用公共后端，只填写连接参数和装配。例如接入 UVC 相机或已有的 ROS 图像话题。
- 设备使用新协议时，插件提供 Adapter。笛卡尔遥操、专用动作和仿真模型按需在同一插件或其配套包内提供。
- 插件依赖公共的描述、端口、样本和生命周期接口。厂商 SDK、型号、地址、校准、设备默认值和私有资源由插件或部署配置持有。
- 本轮范围是组件接入。多机器人控制权分组、共享仿真场景调度和旧 Profile 全量迁移沿各自计划推进。

## 已核实的基线

- 仓库外构建的临时 wheel 经 ament 索引可发现自定义机械臂、数值传感器和双路相机。已验证预设解析、实际工厂加载、fake 机械臂派发和采集入口接收三类数据。采集验证使用记录器替身。
- 现有纯 Python 文档要求在 `morla.component_manifests` 写 JSON 文件路径。使用 setuptools 按该方式构建 wheel 会被拒绝。现有发现测试通过构造已安装元数据验证了读取路径，常规构建流程需要补测。
- 编译与采集可引用 `camera.wide`，Web 预览只读取 `rgb`。Web 添加执行器时预填 `position`，编译器省略采集配置时默认引用 `position` 和 `position_target`。
- `SchemaV3` 与 HDF5 writer 已能描述或写入具名字段，组合采集入口目前主要从反馈构造 `values` 与 `valid`。外部多字段样本需要贯通这一层。

现有依据见 [组件 SDK](SDK.md) · [插件描述](../integrations/PLUGIN_DRIVEN_PORTING.md) · [资源解析](../../src/common/morla_core/morla_core/resource_locator.py) · [组合采集入口](../../src/common/morla_web_manager/morla_web_manager/composable_service.py)。

## 阶段一 · 打通外部安装、发现和资源解析

**改动模块**  `morla_core.plugins`、`resource_locator`、`morla_runtime.plugins`、Web 模板服务和公共仿真资源解析。

1. 采用标准 wheel 的包数据交付一份静态 `morla_plugin.json` 索引。索引声明格式版本、该分发包自带的描述文件和可引用的资源根。用 `importlib.metadata` 的已安装文件清单定位该索引。发现过程只读包数据，工厂继续用现有标准 Python entry point，按所选组件及后端加载。
2. 为模板和模型统一资源解析。以 `plugin_id@version` 的注册来源确定资源归属，解析发行包内相对路径。拒绝绝对路径、越界及不属于该来源的文件。旧 ament 描述仍使用现有 package share。发布验收覆盖普通 wheel 和现有 ament 安装路径，editable 开发安装单独记录支持情况。
3. 让目录按来源收集诊断。坏 manifest 或不可定位的资源应能定位到分发包。重复的组件身份或工厂拒绝歧义，只影响冲突身份；其他已安装组件及与其无关的工作站继续可用。检查选中工厂与描述来源的对应关系，避免不同分发包之间错配。
4. 保留对已有可读的旧 manifest 元数据的兼容读取，新 SDK 示例统一改用实际能构建的形式。预检区分描述已发现、工厂已注册、资源可解析和设备已连接。

**出阶段条件**  在干净环境用标准构建工具构建仓库外插件 wheel，再通过安装产物发现描述、列出预设、读取资源并运行 fake。测试过程不手写 `.dist-info`。导入报错的厂商模块在发现和编译阶段不会被加载。加入一个损坏插件后，另一个有效设备仍可启动。

## 阶段二 · 用端口能力驱动 Web 和编译默认值

**改动模块**  Catalog、装配编译器、`ComposableTab`、采集设置、相机预览 API 和场景构建所用的端口查询。

1. 在 descriptor 增加可选的端口角色声明，表达默认反馈、命令、预览和采集。一个组件可有多个可预览或可采集端口。公共层统一检查方向、语义和编码。已有 `position`、`position_target`、`closure`、`rgb` 走兼容推断；外部组件可使用自己的端口名。
2. Web 添加设备和编译器推断采集布局时，使用同一份已解析能力。显式 Assembly 配置优先，包括显式空采集列表。分辨率、帧率等设备默认值由 descriptor 持有。首批验收夹爪使用自定义开口反馈与目标端口，复用现有标量映射。
3. 相机预览和流式接口用组件实例与端口共同定位。现有仅含组件 ID 的路由继续使用默认预览端口。预检、采集、相机列表和可选仿真支持按已声明能力判断。UVC 和 ROS 图像适配器继续作为可复用后端，外部相机可自带工厂。
4. 接入样例覆盖厂商独有参数。Web 表单使用插件的 `configuration_schema`、字段名称和默认值。若启用参数校验，先覆盖新外部插件声明的 schema 和已合并的最终实例参数，给出字段级错误，沿用旧配置的兼容路径。

**出阶段条件**  从 Web 添加陌生 ID 的夹爪、机械臂、传感器和相机，表单、默认连线和预检自动可用。自定义命名的两路图像均可预览，且能分别选择是否录制。用现有 ament 配置复测 CR5、FR3、EPG 和 MMK2 入口。

## 阶段三 · 贯通结构化传感器样本

**改动模块**  `morla_core.contracts`、`_compile_capture`、Web 组合采集、`ComposableRecorder` 和现有 HDF5 writer。

1. 在现有按端口读取的结构上定义版本化样本。明确字段名、dtype、shape、单位、编码、有效性、来源和时间戳。先覆盖标量、定长向量、固定形状张量和现有 JPEG 图像。多字段样本如压力阵列加温度可从同一端口按字段交付。
2. 编译器根据端口声明和采集选择冻结字段布局。录制校验声明和实际样本一致后，复用现有数值流、sensor sidecar 和图像 writer。现有 `values` 与 JPEG `data` 保留兼容读取。形状、类型、编码和时间异常应能定位到实例、端口与字段。
3. Web 能选择传感器作为独立采集通道。普通传感器记录留在独立流，配置显式映射后才进入模型观测，避免装一个新传感器就改变旧策略的输入维度。深度和点云的编码或预览按新增需求单独推进。

**出阶段条件**  外部多字段 fake 传感器从安装、发现和配置走到真实 HDF5 落盘，重新打开文件能核对字段、dtype、shape、时间戳及有效位。两路 RGB 单独落盘，记录数量和选择一致。旧 SchemaV3 样本仍可读取、对齐和导出，旧模型维度保持原配置的定义。

## 阶段四 · 将零改动接入固化为可重复验收

前一阶段开始前补上对应回归，最终在 CI 中执行完整外部接入验收。扩展现有 fake 一致性检查与 `test_composable.sh`，让来源、发现、编译、预检和录制走实际公开入口。

- **夹爪** 使用外部包的米制开口反馈与目标端口，复用公共标量映射，核对单位及派发值。
- **机械臂** 使用外部包的关节定义和 Adapter。另验证可选 IK 工厂的安装发现及选择加载，模型资源从安装包读取。
- **传感器** 验证仅实现读取接口即可参加采集，检查数值与多字段样本实际落盘。
- **相机** 从同一外部组件选择两个自定义端口，验证分别预览和采集。复测已有 `rgb` API 路径。
- **最小安装** 组合式入口在只安装公共运行依赖与测试插件的环境中通过。若还需要无关机器人包，沿依赖链拆出旧 bringup 或兼容功能，再复测。
- **兼容回归** 复用现有 fake、sim 和 Web 用例。安装一个插件后，既有设备的端口、控制限步、采集布局和冻结数据身份保持原有含义。若升级确需重新编译保存，走显式新 revision。

发布时把可构建样例和公开契约补进 [组件 SDK](SDK.md) 与 [设备接入指南](../device_integration_guide.md)。验收记录区分纯 Python、浏览器、ROS/DDS、仿真和真机。软件接入的验收以外部包安装产物为准，设备的使能、停止和硬件联调另记录实测结果。

## 实施顺序

1. **首个改动** 先添加真实外部 wheel 的构建验收，再交付静态 manifest 和资源解析。外部包可安装、可发现、可启动 fake 后即可独立交付。
2. **第二个改动** 交付通用端口角色、Web 默认配置和多端口 RGB 预览。首批第三方组件用这一阶段验收完整接入体验。
3. **第三个改动** 交付多字段采集与磁盘级回归，随后收敛最小安装依赖及 SDK 文档。历史厂商描述按兼容回归逐个搬迁，移除公共层已有品牌特例时维持原工作站行为。
